# Issue #2128 — integrate gpt-image-2 (complete scope)

This plan delivers the **complete** scope of issue #2128. It does NOT defer any
requirement the issue assigns to this PR. The earlier "bounded first slice"
framing is superseded: generate-only, tool-only, and the deferral of edit mode,
`/image`, and CLI flags are removed.

## Problem and decision

Issue #2128 asks for first-class image generation/editing via the same
`gpt-image-2` backend and ChatGPT/Codex OAuth authentication the Codex CLI uses,
exposed through three entry points (a `generate_image` tool, an interactive
`/image` slash command, and non-interactive CLI flags), backed by a typed
backend-neutral image-generation service with the Codex OAuth adapter as the
first implementation. Edit mode, all three entry points, the output-path
contract, security/operations bounds, and the opt-in real-provider test are all
in scope for this PR.

Decision: extend the existing backend-neutral image-generation application
service and backend contract so a normalized request carries prompt, a REQUIRED
caller-selected output path, zero-to-five input image paths, and a cancellation
signal; and a normalized result carries operation, absolute + workspace-relative
output paths, MIME, backend/provider/model identity, input paths, and
model-visible media metadata. Implement Codex OAuth generate AND edit. Refactor
the existing secure persistence so the caller selects the output path (explicit
`.png`, workspace-contained, traversal/symlink-checked, no silent overwrite,
atomic write, cancellation through provider and file write). Add the
`generate_image` tool surface `{ prompt, output_path, input_paths? }`, the
`/image` slash command with a shared quote-aware tokenizer, and typed yargs
launch flags `-I`/`-O`/`-P` with direct dispatch. The active conversational
provider/model is never touched; image generation never routes through chat
completion.

## Verified Codex behavior (from issue)

- Model: `gpt-image-2`
- Generate: `POST https://chatgpt.com/backend-api/codex/images/generations`
- Edit: `POST https://chatgpt.com/backend-api/codex/images/edits`
- Auth: existing ChatGPT/Codex OAuth bearer token plus `ChatGPT-Account-ID`
- Extra context: `originator: codex_cli_rs`, optional session ID
- Generate defaults: `background: "auto"`, `quality: "auto"`, `size: "auto"`
- Edit requests provide input images as data URLs
- Response: `data[].b64_json`
- Up to five referenced images are supported
- A ChatGPT/Codex subscription suffices; must NOT require `OPENAI_API_KEY`
- Fetch fresh credential object ONCE per operation, not twice and not globally cached

## Architecture

```
/image command ---------\
                         > ImageApplicationService -> selected image backend
generate_image tool ----/
                        \
CLI image flags ---------/
```

All three entry points converge on the SAME service. The service owns input
validation, safe workspace path handling, output validation, atomic writes,
cancellation, and normalized results. The Codex adapter owns Codex
authentication, headers, endpoint selection (generate vs edit), request encoding
(data URLs for edit inputs), and provider response parsing. The Codex image
backend is mounted beside the Codex `OpenAIResponsesProvider` and shares its
resolved OAuth/account context. Image operations never pass through
`generateChatCompletion()`.

## Output-path contract

Every operation requires an explicit output path. There is no hidden
application-data default and no automatic ignore-file management.

- Relative paths resolve against the workspace root.
- Output restricted to the active workspace.
- LLxprt does not modify `.gitignore`, `.git/info/exclude`, or `.llxprtignore`.
- Require `.png`; reject extension/content mismatch.
- Preserve edit sources by default; output must be a separately specified path.
- Do not silently overwrite; apply normal policy/confirmation semantics.
- Validate traversal and symlinks; safe parent creation; validate decoded size
  and PNG signature/structure; atomic write.
- No base64/provider-body leaks; cancellation through provider and file write.

## Slices (each RED/GREEN, tests after each)

1. **Normalized contract + caller-selected persistence** — extend
   `ImageGenerationService` types; refactor persistence to a caller-selected
   output path with full traversal/symlink/overwrite/signature/atomic/cancellation
   behavior; keep existing strict PNG/base64 validation.
2. **Codex OAuth edit mode** — `POST /images/edits` with data-URL inputs, max
   five, fresh credential once per op; generate already implemented.
3. **Input image validation** — MIME/file signatures, symlinks before reading,
   reject URLs, bound count/size, stage-specific errors; never log
   token/account/base64/data URLs.
4. **Shared quote-aware tokenizer + `/image` parser** — single/double quotes,
   escaped quotes, quoted paths with spaces; reject malformed input with usage.
5. **`generate_image` tool surface** — `{ prompt, output_path, input_paths? }`;
   validate all paths before billing; return saved path text + image media; no
   base64 in normal history/telemetry; no model override.
6. **`/image` slash command** — grammar, completion, hints, help registration.
7. **Typed yargs flags + direct dispatch** — `-I`/`-O`/`-P`, conflicts, output
   formats, stream-json rejection, capability error.
8. **Equivalence + active-provider-unchanged tests** — all three entry points
   produce equivalent normalized requests; image ops never mutate the active
   provider/model.
9. **Opt-in real-provider test** — `LLXPRT_RUN_REAL_PROVIDER_TESTS=true`, skip
   on `CI=true`, one generate + one edit, structural assertions, KEEP_OUTPUT.
