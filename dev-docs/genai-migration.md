# `@google/genai` Type Migration (Completed Record)

Part of the Gemini-containment umbrella [#2343](https://github.com/vybestack/llxprt-code/issues/2343). The migration was designed by the foundation PR [#2347](https://github.com/vybestack/llxprt-code/issues/2347) and executed by the downstream issues #2348–#2351, with follow-on cleanups in #2537, #2623, #2627, and #2763. This page is the historical record of that migration: the disposition of every `@google/genai` symbol and the neutral types that replaced them. It is no longer an active guide — the repository has zero `@google/genai` importers today.

Enforcement changed along the way. The migration-era guards (the enclave boundary guard, the agents-neutral gates, the import-inventory baseline ratchet, and the agents naming scanner `providerAgnosticNaming.test.ts`) were retired in [#2628](https://github.com/vybestack/llxprt-code/issues/2628) after measured parity. The permanent rules now live in [gemini-containment.md](./gemini-containment.md); the retirement evidence is [gemini-containment-parity.md](./gemini-containment-parity.md). There is no baseline or allowlist to maintain: the containment gate is a zero-allowlist structural scan.

## End state

- Zero `@google/genai` imports, manifest declarations, or lockfile entries anywhere in the base workspaces.
- The Gemini provider implementation lives in the non-workspace runtime plugin `plugins/google-gemini`, which alone declares the current-generation SDK `@ai-sdk/google`.
- All conversation, tool, request, response, and error surfaces are typed by the neutral layer in `packages/core/src/llm-types/`, exported from `@vybestack/llxprt-code-core` and the dedicated `./llm-types/index.js` subpath.
- The transitional `geminiLegacyAliases.ts` alias module introduced by #2354 was deleted in 0.10.0 (#2537); the canonical event types (`AgentEventType`, `ServerAgentStreamEvent`, `ServerAgent*Event`, `AgentErrorEventValue`, `ServerFinishedOutcome`, `InformationalStreamEvent`) are the sole names in `core/turn.js`, and `GeminiCodeRequest` (formerly `PartListUnion`) was removed with no internal usages.

## The lingua franca: `IContent`

The provider-agnostic conversation model — `IContent` / `ContentBlock` in `packages/core/src/services/history/IContent.ts` — is the **lingua franca**. There are no Google-shaped "neutral" types. Wherever `Part` / `PartUnion` / `PartListUnion` / `Content` / `ContentListUnion` used to appear above the provider boundary, the neutral replacement is `ContentBlock` / `ContentBlock[]` / `IContent`. Tool results, file attachments, and thought content are covered by `ToolResponseBlock`, `MediaBlock`, and `ThinkingBlock`.

## Where the neutral types live

- **Neutral type layer:** `packages/core/src/llm-types/` — the `ModelOutput` / `ModelStreamChunk` envelope, the canonical finish-reason union + `FinishInfo` (providers own their raw→canonical mapping tables locally), `JsonSchema`, `ToolDeclaration` / `ToolChoice`, `ToolCallRequest`, `ToolResultContent` + conversion rules, neutral request types, `ReasoningConfig`, `ProviderApiError`, count/embed types, and grounding/citation types.
- **Exported from the core package:** `@vybestack/llxprt-code-core` re-exports the barrel (`packages/core/src/index.ts` → `export * from './llm-types/index.js'`), and the dedicated subpath `@vybestack/llxprt-code-core/llm-types/index.js` is declared in `packages/core/package.json`.
- **Gemini boundary:** the plugin. `plugins/google-gemini/src/**` is the only source subtree that touches a Google generation SDK (now `@ai-sdk/google`). The former enclave tree `packages/providers/src/gemini/**` moved into the plugin in #2763 and no longer exists; its long-dead `neutralConverters.ts` module had already been deleted in #2234.

## Anti-regression rule

> No Google-shaped "temporary neutral" aliases. There is no `LlxprtPart`, no renamed 1:1 clone of a Google type, and no structurally-Google mirror with a llxprt name. Every neutral type is anchored on `IContent` / `ContentBlock` (the conversation model) or on provider-agnostic protocol shapes. If a genuine gap is found, extend `ContentBlock` with a new discriminated variant — never with an optional-field union that mirrors Google's `Part`.

| ------------------------------- | ------------------------------------ |

## Enforcement history

- **#2352 (the ratchet era):** importers were tracked in a generated baseline (`dev-docs/genai-import-baseline.md`, since deleted) with a decrease-only count check.
- **#2352/#2354 onward:** the enclave boundary guard (`scripts/check-genai-enclave.ts`) and the agents-neutral gates policed imports and naming; the agents package ran its own naming scanner (`providerAgnosticNaming.test.ts`).
- **#2763:** the Gemini provider implementation moved out of `packages/providers/src/gemini/**` into the non-workspace plugin `plugins/google-gemini`.
- **#2628 (current):** the whole guard family was deleted after measured parity and replaced by the zero-allowlist containment gate. See [gemini-containment.md](./gemini-containment.md) for the rules and [gemini-containment-parity.md](./gemini-containment-parity.md) for the differential evidence.

## Using the neutral types

Three before/after examples from the migration. Import the neutral types from `@vybestack/llxprt-code-core` (or the `./llm-types/index.js` subpath).

### 1. `FinishReason` enum → canonical finish-reason union

Before (Google enum, requires `@google/genai`):

```ts
import { FinishReason } from '@google/genai';
if (candidate.finishReason === FinishReason.STOP) {
  /* ... */
}
```

After (neutral union; each provider owns its raw→canonical mapping locally — the Gemini mapping lives in the plugin's `finishReasonMapping.ts`):

```ts
import type {
  CanonicalFinishReason,
  FinishInfo,
} from '@vybestack/llxprt-code-core';
const info: FinishInfo = mapCandidateFinishReason(candidate.finishReason);
if (info.finishReason === 'stop') {
  /* ... */
}
// info.rawStopReason preserves the provider-native string verbatim.
```

### 2. `PartListUnion` tool result → `toolResultContentFromLegacyPartListUnion`

Before (Google `PartListUnion` leaks into every tool's output surface):

```ts
import type { PartListUnion } from '@google/genai';
interface ToolResult {
  llmContent: PartListUnion /* ... */;
}
```

After (neutral `ToolResultContent`; the converter operates on `unknown` with structural checks, no `@google/genai` import):

```ts
import {
  toolResultContentFromLegacyPartListUnion,
  type ToolResultContent,
} from '@vybestack/llxprt-code-core';

interface ToolResult {
  llmContent: ToolResultContent /* ... */;
}

const converted = toolResultContentFromLegacyPartListUnion(rawPartList);
if (!converted.ok) {
  throw new Error(`unsupported tool-result shape: ${converted.error}`);
}
result.llmContent = converted.value;
```

### 3. Synthetic `GenerateContentResponse` → `ModelOutput` + `toModelStreamChunk`

Before (agents synthesize a Google response envelope around neutral provider output):

```ts
import type { GenerateContentResponse } from '@google/genai';
const synthetic: GenerateContentResponse = convertIContentToResponse(icontent);
```

After (providers stream neutral `IContent`; the adapter lifts each chunk onto the typed envelope — no Google type):

```ts
import {
  toModelStreamChunk,
  accumulateModelStreamChunk,
  type ModelOutput,
} from '@vybestack/llxprt-code-core';

let acc: ModelOutput = { content: { speaker: 'ai', blocks: [] } };
for (const chunk of providerStream) {
  acc = accumulateModelStreamChunk(acc, toModelStreamChunk(chunk));
}
// acc.finishReason / acc.rawStopReason / acc.usage / acc.responseId
// are now typed envelope fields (no candidates array, no Google field names).
```
