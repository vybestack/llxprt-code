## Changed behavior

- Anthropic streaming `message_delta` and non-streaming responses parse neutral `stopDetails` with nullable category/explanation and optional recommended model. Malformed external details are omitted while the existing refusal finish reason survives.
- The HTTP `request-id` response header travels independently from the Anthropic message id through provider output metadata, neutral model envelopes, refusal evidence, journal payloads, token records and provider-owned category telemetry. Missing IDs serialize as null on turn records. Accepted retry records do not inherit refusal-only fields.
- Stream finish metadata retains stop details/request ID through later chunks and after-model content replacement. History commits strip these internal fields.
- Retry notices include category and explanation when available. Session/model statistics aggregate deduplicated refusal counts by nullable category and show category counts in `/stats`.
