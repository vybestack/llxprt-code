# Plan: Sanitize LLM-generated Mermaid sequence diagrams in the PR-review walkthrough

Plan ID: PLAN-20260802-MERMAIDSANITIZE
Issue: #2944
Generated: 2026-08-02

## Problem

The automated PR-review "Walkthrough" comment (footer: `Walkthrough generated by
LLxprt PR Review. Planner issue: #2256`) publishes an LLM-generated Mermaid
`sequenceDiagram` **verbatim** with no sanitization. When the model emits a
message label containing a semicolon `;`, Mermaid interprets it as a statement
separator and the whole diagram fails to render ("Unable to render rich
display").

Observed on PR #2938 (comment 5154221688). The two breaking lines were:

    Auth->>Auth: propagate terminal error; no silent fallback
    Tools->>Tools: rethrow; block encrypted-file fallback

Root cause: in `scripts/pr-review-walkthrough.ts`, `buildSynthesisTail()` stores
the raw LLM `diagram` string, and `renderWalkthroughComment()` (in
`scripts/pr-review-walkthrough-parse.ts`) interpolates it directly
(`## Sequence Diagram\n${sequenceDiagram}`). `gateSequenceDiagram()` only decides
*whether* to generate a diagram; nothing validates or sanitizes the content.

## Behavior (acceptance)

- GIVEN an LLM-generated sequence diagram whose message labels contain `;`
  - WHEN the walkthrough pipeline renders the comment
  - THEN the `;` characters in message labels are neutralized so Mermaid parses
    the diagram (no "Unable to render rich display").
- GIVEN an empty or non-`sequenceDiagram` LLM response
  - WHEN the pipeline renders
  - THEN the Sequence Diagram section is omitted (empty string), never broken
    markup (fail fast: drop rather than emit garbage).
- GIVEN a valid diagram with no reserved characters
  - WHEN the pipeline renders
  - THEN the diagram is preserved unchanged (still fenced, structure intact).

## Approach (fail fast, no defense-in-depth)

Sanitize the untrusted LLM output **once**, at the source — immediately after
generation in `buildSynthesisTail` — so every downstream consumer receives clean
data. Do not add redundant sanitization inside the renderer.

`sanitizeSequenceDiagram(diagram: string): string` (pure, in
`scripts/pr-review-walkthrough-parse.ts`):

1. `trim()`. Empty → `''`.
2. Strip markdown code fences (` ```mermaid … ``` ` / ` ``` … ``` `) if present.
3. If the inner content has no `sequenceDiagram` directive → return `''` (drop).
4. For each line that contains a `:`, split at the FIRST colon (everything after
   it is the message label), and replace `;` with `,` in the message portion
   only. Lines without `:` (structure: `participant`, `par`, `alt`, `else`,
   `end`, …) are left unchanged. (`;` is the demonstrated hazard; keep the fix
   surgical rather than speculatively rewriting other characters.)
5. Re-wrap as ` ```mermaid\n<content>\n``` `.

Wire it in `buildSynthesisTail`:

    const rawDiagram = shouldDiagram
      ? await runOptionalStage(reviewDir, prompts.sequenceDiagram, 'diagram')
      : '';
    const sequenceDiagram = sanitizeSequenceDiagram(rawDiagram);

Prompt hardening (soft nudge, `buildSynthesisPrompts` sequenceDiagram prompt):
forbid `;` in message labels/aliases; one interaction per line. The sanitizer is
the hard guarantee; this is the belt.

## Files

- `scripts/pr-review-walkthrough-parse.ts` — add + export `sanitizeSequenceDiagram`.
- `scripts/pr-review-walkthrough.ts` — import + re-export `sanitizeSequenceDiagram`; call it in `buildSynthesisTail`.
- `scripts/pr-review-prompts.ts` — one-line addition to the `sequenceDiagram` prompt.
- `scripts/tests/pr-review-walkthrough-b.test.ts` — behavioral tests (no mocks).

## Test plan (behavioral, real input from PR #2938)

- Feed the exact broken fenced diagram from PR #2938 → assert no `;` remains in
  any message label, the two offending lines now use `,`, structure
  (`participant`/`par`/`alt`/`end`/`/`-aliases) preserved, output fenced.
- Empty input → `''`.
- Non-`sequenceDiagram` input (e.g. `graph TD`) → `''`.
- Clean valid diagram → preserved (fences present, content intact).
- Unfenced `sequenceDiagram` input → wrapped in fences.
- `;` neutralized in messages only; `participant`/`par` lines untouched.
