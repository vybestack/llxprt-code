## The replacement for `registerFakeProviders` and the `fake` seam (ruling d)

`registerFakeProviders` put one `FakeProvider` per name on the manager of a seam-built agent (`LLXPRT_FAKE_RESPONSES` registers only the `fake` provider). The production input is a provider contribution. `helpers/replay-provider-agent.ts` `buildReplayProviderAgent({ initial, targets, storedKeys, configOverrides })` builds the agent through `createAgent` with `providerContributions`: every contributed alias is a `FakeProvider` replaying its script from its first line (a fixture file or inline JSONL), the starting provider is a contributed alias named `fake` with model `fake-model` (so `getProvider()`/`getModel()` before a switch read as before), and the switch targets are further aliases. It throws if `LLXPRT_FAKE_RESPONSES` is set, because the seam would replace the contributions. `{{CWD}}` in a script is the process directory for the starting provider and the agent directory for targets, which is what the seam and `registerFakeProviders` used. `storedKeys` serves named provider keys through a `CredentialAuthority` over an `InMemoryProviderKeyStorage` (the `getKey` spy of `buildProfileAgent`/`buildProfilesAgent` becomes a production input, ruling f). Built-in names cannot be contributed, so every switch target that was `openai`, `anthropic`, `gemini` or `ollama` is a contributed alias (`replay-openai` etc.). `other-provider`, `p` and `newprov` are unchanged.

Assertion-form changes forced by the route, all in the provider name only: `switch-context` T4/T4c/T4d/T4e/T4f/T4dp (`'openai'` becomes `SWITCH_TARGET = 'replay-openai'`; T4c `agent.auth.status('openai')` likewise), `mutationCoverage` (`'openai'` becomes `'replay-openai'` in two scenarios; the property's name list `openai/anthropic/gemini/ollama/fake` becomes `replay-openai/replay-anthropic/replay-gemini/replay-ollama/fake`).

## Decisions

1. `buildReplayProviderAgent` is a new shared helper with a batch-specific name. It is the route by which a test can both start on a replaying provider and switch to another registered one without the seam; other remaining seam users that call `setProvider` should use it.
2. The starting provider is a contributed alias named `fake` (not the seam's built-in `fake`). Production special-cases the name only in `settingsResolver.ts` (`providerName === 'fake'` skips key resolution), which the alias shares by name.
3. T4e writes the LB fixture with a replayable provider into the temp working directory instead of using the committed `profile-load-balancer.json`, because the committed profile names a built-in provider that cannot replay a streamed turn. T4b still applies the committed fixtures unchanged.
