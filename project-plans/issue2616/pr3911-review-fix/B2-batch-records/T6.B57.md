## Unobservable reads

1. Scenario 9 of `recording-shared-history-origin`, `history.addBatch(..., undefined, { afterPublication, origin })` on the session client's `HistoryService`.
   - Needs: the session client's `HistoryService` and the `addBatch` options `afterPublication` (a publication hook that throws) and `origin`.
   - Rows tried: "Client calls that have an `Agent` equivalent" (`getHistory/addHistory/setHistory` only; none takes `afterPublication`); "Listener or subscription counts (... `replaceAll`/`addBatch` origin options)" (a domain-level test of the owner that subscribes or calls: the subscriber is the recording facade, which only the `Agent` builds); "Fault injected on the agent's client" (a real cause through a production input: no production input fails a history publication after it commits, and a failing journal write would change the scenario's stimulus); "Internal identity" (c) does not apply, because the rollback of the prepared recording effects is the property under test.
   - Decision needed: Replaced by a named domain-level test of `HistoryService` plus `RecordingIntegration` (core) asserting that a rejected `afterPublication` leaves no journal entry for either subscriber, naming file and test, or (c) with a covering assertion the orchestrator names.

The file keeps scenario 9 on the old harness (`withRecordingLifetimeFixture`, `fixtureAgentResources`) so the scenario stays unchanged; it is the only remaining user of the old harness in this file. A follow-up `T6.B57b` finishes it after the decision.
