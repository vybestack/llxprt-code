Production facts used:

- `Agent.dispose()` disposes the `SessionClientOwner`; afterwards `agent.getHistory()` rejects `Session client owner is disposed`, `agent.session.*` rejects `Session disposed`. Probed in a scratch test before the edit (deleted).
- `OwnershipRecord.sessionLocks` is never filled in production (`recordOwnership` gets no `sessionLocks`; only `agent-bootstrap.spec.ts` passes any), so the old `ownership.sessionLocksReleased` marker flipped over an empty list. The real lock is the recording lock `<projectChatsDir>/<sessionId>.lock` taken by `agent.session.setRecording({ enabled: true })` and released at dispose (same file effect `recording-finalizer-join.behavior.test.ts` reads through `SessionLockManager.isLocked`).
- `SessionPolicyOwner` subscribes the policy updater on its `MessageBus` at construction and unsubscribes it in `closeAdmission`/`dispose`; `MessageBus.listenerCount(type)` is a public member.
- `WorkspaceExtensionOwner.dispose` releases every active extension through `loader.releaseExtension` -> `unloadExtension`; `McpRuntimeOwner.dispose` runs it, and wraps failures in `AggregateError`s.
- `AgentClient.bindModelNotifications` subscribes to `SessionSettingsOwner.subscribeModelChanges` and `AgentClient.dispose()` releases it; `SessionSettingsOwner.publishModelProfile` is public, and a subscribed idle client drops its chat on it (`invalidateChatForProfileChange`).
