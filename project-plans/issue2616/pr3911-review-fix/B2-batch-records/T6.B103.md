## Decisions

- Policy: the original forced confirmations (`injectConfirmationForcingPolicy`) and added ALLOW rules for `task` and `child_record` on a caller policy owner (`addRule`, observation rule row "Rules added to a caller policy owner"). Production route: the MCP server's `trust: true` (H-c default) gives `child_record` no confirmation, and Route A (`fromConfig`) does not force generic confirmations, so the `task` call and the child call run without a rule. The `decision` parameter of the old `owner()` (ASK_USER, DENY) is used only by `child-tool-owner-owner-4` (B104) and is not carried into the helper; B104 adds it (`trust: false` plus `onApproval`, or `excludeTools`).
- Effects: the original `effects.push(name)` ran in the owner's own `child_record` `MockTool`. Replay arguments are static, so the label cannot travel through the tool call; `effects()` maps each `entered` line of the owner's own MCP server (one server and effects file per owner) to the owner's label. A call reaching the wrong owner's server would still change the other owner's list, so isolation is observable the same way.
- Prompt-system setup (`LLXPRT_PROMPTS_DIR` temp directory, `initializePromptSystem`) and the `explicit-caller-` / `child-fixture-` temporary directories went with the hand-built engine: Route A (`openRouteAAgent`) owns its working directory, and the three scenarios pass without the prompt directory (`after-final-1..3.log`).
- Gates: `started` / `finish` (test-local `gate()` pairs plus the `finishes` list) become the H-c gate (`entered()`, `release()`); the afterEach releases every owner's gate before disposing, as the original released `finishes` before `cleanupOwners`.
- Stable callbacks: the hook's `openClientChannel` and `subscribeChildTools` are defined outside the `renderHook` callback, as in the original; inline arrows re-subscribed on every render and looped (a first attempt wrote a 1.7 GB log; truncated).
- Expect counts: before 2, 4, 9; after 2, 4, 8. The ninth original expect call was inside `waitFor` retries (the count varies with retry timing); no assertion line was dropped or changed beyond the form changes listed per scenario.
- The `SubagentTerminateMode.GOAL` import stays in files 1 and 3; the unused `Agent`, `TaskTool`, `SubAgentScope`, `Config`, provider-manager and runtime-engine imports went with the engine.
- Replaced / Removed counts are 0 / 1 group (the parent-registry stub, see above).
