## Decisions

1. Borrowed second facades (`borrow()`) become independent Route A agents (`adoptAgentClient`, never set in production). Where the second agent must resume the first's recording (`/continue`), it is opened over the first agent's working directory (`workingDir: route.directory`), so both share one chats directory, as T6.B137 does.
2. `useRecordingPrompts()` is dropped; `useFakeResponsesReplay('multi-turn-text.jsonl')` (the old harness default fixture) replaces it for suites that build agents, as in T6.B140. The suites pass without the prompt-directory setup.
3. Old harness `interactive = true` is kept through `openRouteAAgent({ config: { interactive: true } })`.
4. The command-owner fixture is not changed. `useCommandOwners` is still used by `token-metrics-owner.behavior.test.tsx` (a plain agent builder with no capture); `provider-registration-owner.behavior.test.tsx` builds its agents with a local `createAgent` call because it needs `providerContributions`, which `useCommandOwners` cannot pass.
5. Token total read: no `Agent` member returns `HistoryService.getTotalTokens()`. The token-metrics scenario's subject is the hook that production wires to `agent.session.subscribeHistoryTokens` (`App.tsx`), so the reference value is the count each agent publishes to a second subscriber of that same public member. If the orchestrator wants a read independent of the subscription, that needs a `T6.Pk` public read; this batch did not stop for it because the subscription is the production path under test.
