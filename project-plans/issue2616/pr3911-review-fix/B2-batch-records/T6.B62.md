## Scenarios

### 1. `rejects a borrowed client from another Config even when both session labels match`

Assertions: two caller engines with the same `sessionId: 'same-engine-label'` and separate Config, settings, manager and MCP; `fromConfig(right..., rightManager, ..., rightMcp, undefined, capturedSessionClient(leftOwner))` `.rejects.toThrow(/different Config/i)`. Timeout 30000 ms.

Outcome: **Removed**. The rejection is `assertBorrowedSessionClient(this.adoptAgentClient, this.config, ...)` in `#adoptAssertBorrowedClient` (`adopted-agent-assembly.ts:274-279`), reachable only when `adoptAgentClient` is set. Production never sets it (the only writer is `adoption-fixture.ts:111`). A client from another Config cannot be handed to a production route: `createForegroundAgent`, `createAgent` and `fromConfig` accept no client. Not a rollback, isolation, disposal-order or failure-reporting scenario in production terms: the isolation it guards (a facade cannot be given another Config's client) is enforced by the absence of the input, which T6.D1b deletes (`borrowedClient`, `activationSuppliedClient`).

Related production guards that remain and are covered elsewhere: `Activation preflight belongs to a different Config` (`activationPreflightState.ts:471`, preflight receipt vs Config) is exercised by the Route B tests of `activationPreflightState-owner-*` and `post-config-preflight.test.ts`.

### 2. `transfers one borrowed preflight owner without closing the caller client, manager, media or MCP`

Assertions: caller engine built; `captureActivationAcquisition(..., () => 'agent', 'borrowed', client, builtMcp)` runs `operation.preflight(intent)`; `fromConfig(..., { activation: intent }, ..., { operation, token }, client)` adopts the receipt; `publishedClient(agent)` `toBe(client)` and `toBe(capturedSessionClient(capturedActivation(operation).owner))`; after `agent.dispose()` and `builtMcp.refreshContext()`, `client.addHistory(...)` works and the human history has length 1, `builtMedia.store.getStoredByteLength()` is `0`, `builtManager.getActiveProviderName()` is `'fake'`. Timeout 30000 ms.

Outcome: **Removed** (whole scenario). Every assertion is about a caller-owned client, manager, media store or MCP runtime surviving the agent's disposal, or about the agent's client being the same object as the caller-supplied one (internal identity). Each needs `activationSuppliedClient`/`activationMcp` (never written in production; `profile-preflight.ts:693-709`), `adoptAgentClient`, `adoptMcpRuntime`, `adoptProviderManager` or `adoptActivationPreflight` (none set in production). In production the preflight owns the client, manager, media and MCP, and `agent.dispose()` is their only closer, so "does not close the caller's X" has no caller to protect. The production-reachable half (an agent built from a preflight receipt is usable and disposes what it owns) is carried by existing Route B tests that stay in the tree: `post-config-preflight.test.ts` > `constructs the foreground Agent privately from its accepted activation (borrowed true|false)`, `keeps preflight history with the adopted session and closes captured reads on retirement`, `publishes the acquired session without distributing individual owners`, and the Route B `activationPreflightState-owner-*` scenarios. Internal identity lines dropped with the scenario: both `publishedClient(agent)` `toBe` lines, whose covering behavior is `keeps preflight history with the adopted session ...` (history written before the agent is built is visible through the agent). No assertion is carried over, so no reassertion in a new form is needed.
