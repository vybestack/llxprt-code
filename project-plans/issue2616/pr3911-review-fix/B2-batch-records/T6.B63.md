## Decisions

- Engine 1a, 1b and 2 use two `fromConfig` facades over one test-owned `Config` (the first from `openRouteAAgent`, the second from `fromConfig(first.config, seededSettings, { activation }, first.authority)`), the closest production-reachable form of the original shared engine. Each facade builds and owns its client, manager, media and MCP. The failure case passes `{ activation: { provider: 'missing-shared-provider' } }` and still rejects `/activation failed/i`.
- Engine 3 media lifetime: the standing ruling for store lifetime with no public read is used. The human item carries a base64 PNG block so the store creates its directory, `<projectTempDir>/media-live/*` has one entry while the agent is open and none after `dispose()`. `projectTempDir` is read from a second `Config` built from the same `workingDir` (the path is derived from the storage root only), disposed in `finally`. The `/disposed/` read moves from the internal published-client lookup to `agent.getHistory()` rejecting after `dispose()`. The assertion that `getStoredByteLength()` rejects `/closed/` is replaced by the filesystem effect, an assertion-form change forced by the route.
- Join 1: client factory returns the real client from `buildAgentClientFactory()` and the test replaces that instance's `dispose` (same gates, same fetch inside cleanup). `capturedSessionClient(builtOwner)` becomes the last client in `ownerClients(builtOwner)` (the first inline-engine client is replaced during activation, as T6.B30 found). The `LLXPRT_FAKE_RESPONSES` set/restore moves to `useFakeResponsesReplay('multi-turn-text.jsonl')`.
- Join 2: the leg `candidate = builtOwner.prepareProfileActivation(...); candidate.publish(); await candidate.retire();` has no public trigger on Route B (the candidate is an internal of the session owner the preflight does not expose before an agent exists) and is dropped. The file is retained through `preflight.retainProviderFile` and released (`lease.release()`) as before, `access(file)` and `retainedFiles` 1 are asserted before `preflight({ provider: 'fake' })`, and the four post-dispose assertions are unchanged. `preflight-release.behavior.test.ts` > `closes credentials and retained files before Config exists` and `joins concurrent close while a real lease holds file deletion` cover the pre-Config half. The retained-file scope is the host runtime id (`profile-preflight.ts` `retainProviderFile`), not the Config session id. The two concurrent disposals are `route.disposePreflight()` and `route.preflight.dispose()`.
- Dropped lines (Removed or internal identity, each with its covering assertion): engine 1a/1b caller history length 2, caller media store 0 and caller manager `'fake'` (caller lending, `adoptAgentClient`, `adoptMcpRuntime`, `adoptProviderManager`, `adoptMessageBus`); covered by the surviving facade's history length 1 after the sibling closes. Engine 2 caller `addHistory` and length 2: same citation; covered by the survivor's history length 1 after the failed sibling. Engine 3 published-client throw `/disposed/`: replaced by `agent.getHistory()` rejecting `/disposed/`.
