## Decisions

- ASK_USER: the child MCP server is declared `trust: false`, so the child's MCP call asks for confirmation; the mounted hook (the confirmation consumer) shows `awaiting_approval` with the confirmation's `onConfirm`, as before. Rule row: "`ASK_USER` is the absence of an allow rule plus a confirmation consumer".
- DENY: `AgentConfig.policy` (public input, maps to `ConfigParameters.policyEngineConfig`) with a DENY rule (priority 10000) for the child tool plus an ALLOW rule for `task`. The policy engine names an MCP tool `<server>__<tool>` (`recording__child_record`), not the catalog name `mcp__recording__child_record`. `excludeTools` was tried first and rejected: it removes the tool from the registry, so the child never schedules a call and the non-primary status list is `[]` instead of `['error']`. A non-interactive agent was also tried and rejected: the child's non-interactive executor rejects the call before the scheduler, again with no child call. With the policy rule the child call completes `error` ("Policy denied execution of tool"), the original assertion.
- Concurrent owners: each owner has its own MCP server, effects file, gate, working directory and `Config` (the fixture's existing design); `LLXPRT_FAKE_RESPONSES` is process-wide but all owners in a file use the same read-only replay, restored in reverse creation order.
- Streaming (owner-5): `DiscoveredMCPTool` is built with `canUpdateOutput: false`, so an MCP child tool cannot produce the `append` output update the scenario asserts (`renderer streaming child work`). The fixture option `streamingShellText` makes the child run the built-in `run_shell_command` (observation rule approach (a), "a built-in tool with a physical effect") with a per-owner replay file written into a temp directory: it prints the text (the shell tool streams cumulative `append` updates), appends a line to an `entered` file and waits for a `release` file. `allowedTools: ['run_shell_command']` removes the confirmation. Assertions unchanged.
- Result text (main test): option `outputText` selects `createGatedEchoMcp` (T6.B60) with server name `recording`, so the tool name and replay are unchanged; the answer is `<outputText>:undefined`.
- Fixture additions (backward compatible; B103 callers pass no third argument): `openChildToolOwner(name, mounted, options?)` with `decision`, `outputText`, `streamingShellText`; `ChildToolOwner.childAgentIds()`; the gate is an internal `ChildToolGate` with MCP and shell implementations; `runTask` and `openGate` were extracted to stay under the function-length rule.
- Expect counts: before 15, 3, 13; after 17, 3, 14 (the difference is `waitFor` retries and the added `displayedA`/`displayedB` definedness checks; no assertion line was dropped).
