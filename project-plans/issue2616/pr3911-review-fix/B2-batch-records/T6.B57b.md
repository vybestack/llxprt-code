### Replaced test and added coverage (file and tests)

`packages/core/src/recording/RecordingIntegration.sharedHistoryOrigin.test.ts`, describe `RecordingIntegration shared history batch origin`. Built over a test-built `HistoryService` with two `RecordingIntegration` subscribers, each with its own owner object and its own real `SessionRecordingService` journal in a temp directory; a seed added with no origin materializes both journals.

- `rolls back both prepared recording effects when afterPublication rejects an unbound or owned batch` (Replaced scenario 9): `addBatch([...], undefined, { afterPublication: throw })` and `addBatch([...], undefined, { origin: <first owner>, afterPublication: throw })` both reject with their messages; neither journal contains `rolled-back-marker` or `owned-rollback-marker` (both still contain the seed, so the journals were read).
- `delivers an unbound batch, which has no origin, to both subscribers` (the unbound `addBatch` path scenario 5 no longer exercises): a successful `addBatch` with no options puts `unbound-batch-marker` in both journals.
- `delivers an owned batch only to its owner` (contrast for the origin rule, added so the unbound test cannot pass by delivering everything everywhere): `addBatch` with `origin: <first owner>` puts `owned-batch-marker` in the first journal and not in the second.
