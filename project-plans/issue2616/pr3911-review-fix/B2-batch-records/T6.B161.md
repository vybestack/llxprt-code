## Decision: "which client is current"

Orchestrator ruling: observe through an effect (instance-wrap a method on each real client created through the owner's factory, drive the next public operation), not the `getCurrentSequenceModel` probe. Applied as follows.

- Fault injection on the owner's real client (unreadable `restoreHistory`, `resetChat`, `setHistory`): the test spies the method on every client in `ownerClients(owner)` (all real clients the production factory built, creation order); the production path (`session.restoreHistory` and friends through the owner's active client) reaches the spy of the current one. Nothing is asked about which client that is.
- Current history service (adding the first message in `unreadable`, `providerSwitchRecording`): `readCurrentOwnerHistory(owner)` instance-wraps `getHistoryService` on each `ownerClients(owner)` client, drives the public `owner.nativeHistory.hasHistory()` (which calls the active client's `getHistoryService`), reads which wrapper fired and its result, and removes the wrappers. The probe method is `getHistoryService`, the method whose result the test wants, not `getCurrentSequenceModel`.
- Stats subscription in `uiSessionOwner.ts`: `SessionClientOwner.observeStats(listener, metrics)` is the production member that does exactly what the fixture reimplemented (it reads the active client's history service). The fixture calls it; no client read.
- `uiSessionOwner.ts` `client` getter: its one reader (`directoryCommand.test.tsx`) calls `client.addDirectoryContext()`; the owner's `conversation.addDirectoryContext()` is the public delegation to the active client. The getter is deleted.
- `continuePackageResume`: the test builds its own client (`createAgentClient`) and passes `() => client` as the factory. The client is a test-owned value, not a captured one; `createConfig` returns it and the test uses it directly.
- `auto-prompt-explicit-client`: the captured `client` field is returned but no scenario reads it; the field and its read are deleted.
