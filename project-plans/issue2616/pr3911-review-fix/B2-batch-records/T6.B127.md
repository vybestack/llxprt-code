## Migration decisions

- Trigger: `resolveCompressionProvider(...)` (a core function imported by relative path from agents) becomes the public `agent.compress()` with `compression.profile` set through `agent.setEphemeralSetting`. The production caller is `ChatSession.resolveCompressionProvider` (`chatSession.ts:555`), reached from `agent.compress()`. The profile (`standard` or load-balancer with member `compression-member`) is saved through the real `ProfileManager` into a temporary `LLXPRT_CONFIG_HOME`, so the production profile reads load it.
- The hand-made `providerRuntime`, `runtimeState`, `prepareProviderInvocation` (formerly `fixtureAgentResources(...).prepareInvocation`), `profileDefinitions`, `readProviderKeys`, `resolveExplicitCompressionProvider` and the captured `Config` drop out: production fills them.
- Delegated provider: the prototype spy on `FakeProvider.prototype.generateChatCompletion` is replaced by a provider registered as a provider contribution (`providerContributions`, a public plugin contract) whose request handler builds the header table from `options.invocation` and records the invocation. The profile names the contributed alias as its provider (the earlier profile named `openai-responses` and the stub resolver returned the fake provider; production resolves a profile's provider by name through the manager, and a built-in name cannot be contributed). The headers are still built by `buildResponsesHeaders` / `buildWebSocketHandshakeHeaders` with the same codex-mode `deps`, so the assertions test the same header builders on the production invocation.
- "Outer" table (the `resolved.invocation` returned by `resolveCompressionProvider`): the public path does not return it. Per the slice, the same table is asserted on the first delegated invocation; the runtime-id exclusion uses `agent.getRuntimeId()` (the outer compression runtime id is `<runtimeId>::compression-profile:<name>`, which also must not appear).
- The contributed provider is a small local class in the test file, because the H-b helper lives in `packages/agents/src/api/__tests__/helpers/` and the batch protocol forbids cross-package test-helper imports from providers. Tool-free; it answers one `ai` text block.
- The agents internals imports (`agentHarness.js`, `CompressionProfileResolver.js`, `agent-resource-capture.js`) are removed; the agent comes from `@vybestack/llxprt-code-agents` (`createAgent`).
