### Finding: scenario passes only because the prompt system is broken

`child-task-tool-lifetime` "joins cancellation during child preparation without starting a model after disposal" (unchanged assertions) runs second in its file. At the base commit (old adopted fixture, copied unchanged to a scratch file) it passes in the full file because the child run fails with `Core prompt not found` (the first test's teardown leaves the process prompt system uninitialised). Run alone (healthy prompt system) the old fixture hangs in `await settled`: the disposed-during-preparation child still starts its model request (the held `/v1/child` route sees `fetch-entered`). So `SubAgentScope.dispose` during preparation does not stop the model start; the scenario's claim is not true of production and was masked. Not caused by this migration and not fixed here (no assertion changed). The migrated scenario keeps passing in the full file by the same masked path; `openClientOwner` cannot be used there because its `startChat` fails on the same broken prompt system, so that scenario builds the registry by hand as scenario 1 does. Needs an orchestrator decision (production fix to scope disposal during preparation, then the test should initialise the prompt system).
