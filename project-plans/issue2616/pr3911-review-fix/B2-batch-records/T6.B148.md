## Unobservable reads

1. `chatOwnerCommand.test.ts` scenario 4 (`preserves live and durable history on restore failure and does not repaint UI`). Read/injection it needs: `restoreHistory` on the session client succeeds (history published) and then throws, so `commitRecordedHistoryMutation` (`sessionControlHistoryMutation.ts`) must roll back the live history with `client.setHistory(history)` and the recording with `restoreRecordedHistory`. It was injected with `spyOn(client, 'restoreHistory').mockImplementationOnce(...)` on the capture-obtained client (`resources.client`). Observation-rule rows tried: "Fault injected on the agent's client": (a) a real cause through a production input. `restoreHistory` can fail for real only in `historyAdmissions.admitRetainedHistory` (local media admission, `retainedHistoryAdmissions.ts`) or in the `afterPublication` cleanup (`Restored history publication cleanup failed`); both need local-media history with a media store that fails admission or release, and no public input produces that (`agent.setHistory` admits the same media first). The subject is the Agent's session, not an owner built through a client-factory parameter, so the domain-level form does not apply. Stop rule applied: the scenario is unchanged and still builds through `withRecordingLifetimeFixture` (borrowed recording fixture), so this file keeps that one import until the orchestrator decides.
