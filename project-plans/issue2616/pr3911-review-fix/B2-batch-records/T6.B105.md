Outcome: **Kept** (agent-level, Route A; disposal order, never Removed). Form changes forced by the route: `await a.entered.promise` becomes `await a.entered()`, `a.finish.release()` becomes `await a.release()` (the MCP gate), and the request is built by `a.request('stable')` (the tool's production name replaces the `MockTool` name `external_record`). The captured client's `.startChat()` becomes one `agent.chat('Start the conversation')` turn in the helper (Observation rule row "Client calls that have an `Agent` equivalent": a turn starts the chat). The setup turn adds a user and an assistant message; the assertion filters `tool_response` blocks only.

## Decisions

- Tool identity: the MCP tool's agent-facing name (`mcp__recording__external_record` family) replaces `external_record` in requests and in the DENY rule. The helper reads it from `mcp.tool(agent)` after discovery, so it never hard-codes the qualified name.
- Effects: the original `effects.push(name)` ran inside the `MockTool`. `effects()` maps each `entered` line of the owner's own MCP server (one server and effects file per owner) to the owner's label. A call reaching the wrong owner's server would change the other owner's list, so isolation is observable the same way.
- Gates: `entered` / `finish` (test-local `gate()` pairs plus `releases`) become the H-c gate; afterEach releases every owner's gate before disposing, as the original released `releases` first.
- Prompt-system setup (`LLXPRT_PROMPTS_DIR` temp directory, `initializePromptSystem`) and the `explicit-caller-` temporary directory went with the hand-built engine: Route A (`openRouteAAgent`) owns its working directory, and the three scenarios pass without the prompt directory.
- Expect counts: before 5, 7, 8; after 5, 7, 8. No assertion line was dropped or changed beyond the form changes listed per scenario.
- Policy: the DENY rule names the MCP tool `${serverName}__${toolName}`; the scenario proves it applies (the denied owner records no effect and reports `error`, while its peer built the same way succeeds).
- Stable callbacks: the hook's `openClientChannel` and `subscribeChildTools` stay defined outside the `renderHook` callback, as in the original.
