## Orchestrator ruling applied

"Which client is current after a rolled-back replacement" is observed through an effect, not the `getCurrentSequenceModel` probe. New helper `helpers/owner-current-client.ts` exports `currentOwnerClient(owner)`: it wraps `getHistory` on the instance of each client the owner's factory returned (`ownerClients`), drives the owner's public `owner.conversation.getHistory()`, restores the instances, and returns the one client whose wrapped method ran (the helper throws unless exactly one client ran it). Nothing is patched on a prototype; the sequence-model probe is not used.

## Fault injection moves from subclass to instance wrap

The four test-local `extends AgentClient` classes (`BindingFailureClient` x3, `CountingClient`) were the "fault injected on the agent's client" row: the Kept form wraps the real client on the instance instead of subclassing a production class. Each factory now builds `new AgentClient(...)` (same constructor arguments as before) and wraps the faulted methods on that instance, calling the original through `.call(client, ...)`. Behavior is unchanged (same errors, same order, same counters).
