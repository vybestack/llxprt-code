- Row "Fault injected on the agent's client": (a) real cause. `SessionClientOwner.dispose` (`session-client-owner.ts:520-570`) awaits hooks (`disposeHooks`, composed only by `bindHooks`, which the pre-Agent route never calls), the owner's `work` queue, `toolCatalog.dispose`, `imagesClosing` (the pre-Agent route composes no image runner, so `activationOperation.sessionClient.runImageOperation` rejects `Missing explicit image composition`), the client's `auxiliary.close()` (no public way to start auxiliary work before the Agent exists), the policy writes and `providerLife.close()` (`activationProviderLifetime = () => preflight.#release.close()` is `'borrowed'`-style for this owner; `AgentProfilePreflight` exposes `captureProviderFiles` and `retryProviderFileCleanup` but no `retain`). The public work (`readHistory`, `refreshAuth`, `runImageOperation`) is joined by `#disposeAcquisition` before the client disposal starts (`Promise.allSettled([this.#tail, ...this.#publicWork])`), so holding it does not hold the client's disposal and would test a different ordering. No production input reaches a held or failing client disposal.
- Domain-level form (owner built through its production `create`): the ordering under test lives in `AgentActivationBootstrap.#disposeAcquisition` (protected constructor, built only by `prepareAgentPreflight`); `acquireSessionClient`'s client factory is not an input of that route (B94: "the preflight path has no factory input").
- Row "Internal identity" (c): not applicable; the held disposal is the fault, not an identity.
- Media store: the standing ruling for store lifetime (observe `<config.projectTempDir>/media-live/*` present while open, removed on close) covers the store read once a hold exists; it is not the blocker.
