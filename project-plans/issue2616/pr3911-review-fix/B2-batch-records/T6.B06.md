## Final shapes and decisions

### activationPreflightState.behavior (Kept)

Route B: `openRouteBPreflight({ authority: credentials().authority, config: { interactive: true } })` under `useFakeResponsesReplay('plain-text.jsonl')`, `route.prepare()`, the activation from `transferActivation`, `activation.preflight(intent)` for the token, `activation.readHistory()` before adoption, `AgentProfilePreflight.createForegroundAgent(route.preflight, token, intent, {})`. Kept assertions: token present; `route.config.getContentGeneratorConfig()` `toBe` the object read before adoption; replay rejects. Dropped line (Internal identity, row (c)): `fixtureAgentResources(agent).publishedClient(agent)` `toBe(client)`; covered in the same scenario by `expect(await agent.getHistory()).toStrictEqual(history)` (history read from the activation before adoption, as `post-config-preflight.test.ts` does) and by the content-generator-config `toBe` (a second client would re-run `refreshAuth` and replace that object). The preflight client's history is empty, so the history assertion alone would not catch a client swap; the config `toBe` is the discriminating one.

Message change (decision needed 1): the replay assertion `rejects.toThrow('Activation preflight')` becomes `rejects.toThrow('Foreground construction was already accepted')`. The token-validation message `Activation preflight token is invalid or already consumed` is reachable on the production route only for an unconsumed-but-wrong token (covered by T6.B03 `activationPreflightState-owner-1`). A replay of a consumed token takes `createForegroundAgent`'s first guard (`profile-preflight.ts` `Foreground construction was already accepted`). Replaying through the transferred `AgentActivationBootstrap.createForeground` instead (the slice's suggestion) gives `Activation bootstrap is disposed`, which does not contain `Activation preflight` either (probe run, not kept). The slice allows recording a message change.

### adoption-binding-failure (Kept, route changed from the slice's Route A to Route B)

Route A (`fromConfig`) cannot take the slice's route: the memory owner on Route A is built inside `fromConfig`, so no production input closes it, and the created `SessionClientOwner` has no public read on a Route A agent that was never published (the agent is the thing that failed). Route B reaches both: `openRouteBPreflight({ authority })`, a test-built `SessionSettingsOwner` passed to `route.prepare({ settingsOwner })` (borrowed settings, approach (b)), the activation from `transferActivation`, the host's own `route.memory.dispose()` (the host owns the memory it passes to `preparePostConfiguration`), then `route.createAgent()`. Same failing step as before: `client.bindMcpRuntime` in `#completeForeground` after the session client exists, before the facade is published; same message `Workspace memory is disposed`.

Assertions: failure is an `Error`, not an `AggregateError`, `toMatchObject({ message: 'Workspace memory is disposed' })`; `credentials().snapshot()` `[1]`; `callerSettingsOwner.writeUserParameter('maxOutputTokens', 37)` visible in `route.settings.get('maxOutputTokens')`: all unchanged.

Same claim (the created session client is retired); the "exactly one" count has no public read and is dropped. Orchestrator to accept or name a domain-level Replaced target.
