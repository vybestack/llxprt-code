## Unobservable reads

1. owner-9: the test holds the first attempt inside `claudecode`'s `hasNonOAuthAuthentication` and then runs a second attempt on provider `fake`, ending with `getActiveProviderName() === 'fake'`. Rows tried:
   - Observation rule row "Provider key reads" (approach (b)): a `CredentialAuthority` over a `CredentialProxyServer` with a gated `InMemoryProviderKeyStorage` would hold the key read behind `hasNonOAuthAuthentication`. That requires a registered `claudecode` provider.
   - "Registered provider on a caller manager becomes a `providerContributions` entry": a contribution cannot reuse the built-in id `claudecode` (the registry rejects every collision with a built-in), and `prepareAgentPreflight`'s `contributions` is not exposed by H-e (`openRouteBPreflight` has no such option).
   - The conflict: `fake` is registered only when `LLXPRT_FAKE_RESPONSES` is set, and then `populateProviderManager` registers only `FakeProvider` (`providerManagerInstance.ts`, `tryActivateFakeProvider` returns before any built-in provider or contribution is registered), so `claudecode` does not exist. With the env var unset, `claudecode` exists and `fake` does not. No production input yields a manager holding both, which the scenario needs (hold on `claudecode`, final active provider `fake`, and `'fake'` is asserted).
   - Replacing `'fake'` by a contributed alias would change an assertion, which the protocol forbids.
   Orchestrator decision (option (b)): owner-9 becomes follow-up batch T6.B05b. The `'fake'` provider assertion literal is replaced by a contributed recording alias (the assertion's meaning, that the latest attempt's provider wins, is unchanged), once H-e gains `contributions` (in progress in another lane), and the held first attempt uses `helpers/gated-key-storage.ts`. Removed-with-citation stays unavailable because the behavior happens in production.
