# T6.B115 batch record

File (6 points): `packages/cli/src/integration-tests/provider-switching.integration.test.ts` (L, 13 scenarios in two suites). Uses H-e (`openRouteBPreflight`). No new helper. Corrections-table row: CSC (`capturedSessionClient(owner)` becomes an Observation-rule read).

Baseline (before any edit): `tmp/pr3911/T6.B115/before-1.log`, EXIT 0, 13 pass, 44 expects.

Route and decisions. The old tests hand-built an agent over a caller-owned provider manager (`initializeTestAgent`, `adoptProviderManager`/`adoptSettingsOwner`, no production writer) and registered mock providers on the manager. They now build through the foreground preflight route (Route B, `openRouteBPreflight`): mock providers (`providerA`, `providerB`, `gemini`, `other`) are provider contributions (observation rule "`.manager` reads": `registerProvider` on a caller manager becomes a contribution entry; the names are not built-in ids). The test keeps the mock objects, so `vi.fn` instance wrappers and `getDefaultModel` overrides stay on objects the test owns. `switchActiveProvider(...)` with a caller manager becomes the production switcher `preflight.captureSwitchOperation()` (the function the CLI's `postConfigRuntime.ts` uses; it wraps `switchActiveProvider` with the preflight's own manager, settings, OAuth manager and session client `refreshAuth`). `providerManager.setActiveProvider/getActiveProviderName/hasActiveProvider` become the same-named `AgentProfilePreflight` members. The test's own `SessionSettingsOwner` over `route.settings` is passed as `prepare({ settingsOwner })` (production borrowed-settings input), so `settingsOwner.writeUserParameter/readSelectedModel/chooseModel` stay. Suite 1 builds the foreground Agent (`route.createAgent`) because its scenarios read `getEphemeralSetting`, `setEphemeralSetting` and `providerReads.getActiveModelParams()`; suite 2 never reads the agent and uses the preflight only, which keeps "no active provider before any selection" true. Mock `openai` and `anthropic` (suite 2 and scenario 6) are built-in provider ids, so they are not contributed: the built-in providers are used (scenario 6 asserts the alias default model `gpt-5.5`, which comes from the alias config, not the provider object).
