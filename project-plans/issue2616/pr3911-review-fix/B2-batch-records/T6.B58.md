## `runtime-owner-bindings.test.ts`

| # | scenario | assertions | outcome |
| --- | --- | --- | --- |
| 1 | `keeps the construction runtime id when the owned Config adopts another session id` | `config.getSessionId()` `adopted-config-session`; `agent.getRuntimeId()` `construction-runtime-id` | **Kept**, agent-level Route A (see below) |
| 2 | `assigns independent provider-file owners to public Agents sharing a session label` | `agent.captureProviderFiles` of the two agents differ; Configs differ; concurrent `setProvider` gives models `[switched-model-0, switched-model-1]`; both `generate` give `turn one reply`; after `agents[0].dispose()` its `generate` rejects `Agent is closed`; `agents[1].generate` gives `turn two reply` | **Kept**, Route C; one internal-identity line dropped under (c) |
| 3 | `keeps same-label profile, credential, factory and cleanup owners separate through interleaved activation` | per-agent temperature and model name; key lifetime `[[activated],[activated]]`; failed `createAgentWithRetainedProviderFiles` rejects `activation rejected`, key snapshot `[1]`, failed file deleted; survivors intact; dispose order snapshots; tokens kept; factory events non-empty and `'providerManager' in config` false | **Kept**, Route C; the two factory-capture lines dropped under (c) |
| 4 | `disposes only the exact file owner when public Agents share a runtime label` | deleted/retainedFiles/closed assertions | **Kept**, Route C, no change |
| 5 | `switches and saves distinct provider profiles ...` | profile, model and diagnostics assertions | **Kept**, Route C, no change |

Decisions:

- Scenario 1: the wrapper called `config.adoptSessionId('adopted-config-session')` from inside `agentClientFactory`. `runtimeFactoryBindings` is not an observation input, and no production input runs code during client construction. The scenario's subject (the runtime id does not follow the Config's session id) is observed on Route A: the test owns the `Config` (Observation rule row ".settingsService / internalConfig reads", approach (b)), builds the agent with `config.sessionId` and `intent.sessionId` both `'construction-runtime-id'` (`fromConfig` takes the runtime label from `intent.sessionId`, a field `AgentAdoptionIntent` keeps), calls `config.adoptSessionId('adopted-config-session')` on its own Config after the agent is built, and asserts the same two expectations. Assertion-form change forced by the route: the adoption happens after construction instead of during it; `agent.getRuntimeId()` is read after the adoption. Env `LLXPRT_CONFIG_HOME` handling stays as written.
- Scenario 2: dropped line `expect(configs[0]).not.toBe(configs[1])` (internal identity of the Config the client factory received, readable only through the factory capture). Approach (c). Covering assertions in the same scenario that fail if the two agents shared a Config: the concurrent `setProvider` gives per-agent models `[switched-model-0, switched-model-1]` (a shared Config would end on one model), and `agents[1].generate('survivor')` works after `agents[0].dispose()`. `owners[0] not.toBe owners[1]` stays: it reads the public `agent.captureProviderFiles` members.
- Scenario 3: dropped lines `expect(factoryEvents.every(...length > 0)).toBe(true)` and `expect('providerManager' in args[0]).toBe(false)` (both read the Config the client factory received). Approach (c). Covering assertions: each agent keeps its own model params (`0.2` and `0.8`) and diagnostics model name through the interleaved construction, the failed construction and the sibling's dispose; the key lifetime snapshots and the per-store tokens prove credential and cleanup owners stay separate.
- `runtimeFactoryBindings: createAgentRuntimeFactoryBindings()` passed to `createAgentWithRetainedProviderFiles` is removed (the field goes in T6.D2b). `createAgentRuntimeFactoryBindings` is no longer imported.
