## Assertion-form changes

- `base-url-behavior` scenario 4: the second provider is the contributed alias `switch-target` instead of `anthropic`. The mock `anthropic` cannot be contributed (`Contributed alias 'anthropic' ... collides with provider id 'anthropic'`), and the built-in `anthropic` provider has its own default base URL, which the production switch writes (`provider-switch-execution.ts:63`, `settings.setProviderSetting(selection.name, 'base-url', selection.baseUrl)`), so `getProviderSettings('anthropic')['base-url']` is `https://api.anthropic.com/v1`, not `undefined` (observed in the first run). The mock had no base URL. The expectation (the previous provider's base URL is cleared and the new provider carries none) is unchanged; only the provider id string in the switch call and in that `expect` key differs. `openai` stays the built-in provider there.
- `base-url-behavior` scenario 3: `gemini` is a contributed mock alias (the built-in registry has no `gemini` in this route: `Provider 'gemini' not found`), as in T6.B115.
- `consumer-migration-p13` scenario 3: `manager.listProviders()` is `agent.providerReads.listProviders()` (Observation rule, `.manager` reads); the manager tap and `registerProvider` are replaced by a provider contribution. The `providerFileLifecycle` and `retainedFiles` lines are unchanged.
- Every `switchActiveProvider(name, {}, config, settings, manager, null, undefined, () => client.refreshAuth(), settingsOwner)` call is `switchProvider(name, {})` on `preflight.captureSwitchOperation()`; `sessionRoot.*` reads are the foreground `Agent`'s (same member names); `providerManager.setActiveProvider` is `preflight.setActiveProvider`.
- `consumer-provider-switching`: the unused `managerReleases` cleanup scaffolding (nothing pushed to it) was deleted with the migration.
