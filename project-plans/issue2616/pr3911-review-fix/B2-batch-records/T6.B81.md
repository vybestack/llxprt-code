## Production failures

Both are Kept scenarios in `workspace-definition-transfer.behavior.test.ts`, migrated to Route C with assertions unchanged. Log (both failures in one run; `production-failure-2.log` is a copy): `tmp/pr3911/T6.B81/production-failure-1.log`.

1. `closes and drains a transferred definition root` (migrated from `closes and drains a transferred definition root without retiring the borrowed workspace`; only the title lost its borrowed-workspace clause). Failing assertion: `expect(() => definitions.profileReads.listProfiles()).toThrow('closed')`, evaluated synchronously right after `agent.dispose()` is called while an accepted `loadProfile('held')` is parked on the gated read. On the `createAgent` route the call does not throw ("Received function did not throw; Received value: Promise { <resolved> }"). A probe (deleted, not committed) showed the root still open for 6 microtask ticks after `dispose()` is called and closed from tick 6 on: `McpRuntimeOwner.closePublicationResources` (`mcpRuntimeAssembly.ts:766-780`) awaits `reconfigurationOperations`, `workspaceExtensions.joinAccepted()`, `initialization`, `discovery`, trust and context operations before `if (this.ownsDefinitions) this.workspaceDefinitions.closeAdmission()`. The old adoption route closed admission synchronously (`adopted-agent-assembly.ts:656-657`, `this.adoptDefinitionOwner?.closeAdmission()` in the dispose prelude). Every other assertion (drain until the gate is released, `finished` false after 20 ms, true after) is not reached. A new read admitted in that window is accepted after `dispose()` started.
2. `cleans a transferred definition root when adoption fails before session preparation`. Failing assertion: `expect(() => definitions.profileReads.listProfiles()).toThrow('closed')` after `createAgent({ sessionId: '', definitionOwner, definitionOwnership: 'agent' })` rejects with `AgentBootstrapError: Invalid runtimeId: expected a non-empty string but received ""` (the `'non-empty'` assertion passes). The root is still open: validation (`parseAgentConstruction`/`validateAgentRuntimeId`, `agent-construction-input.ts`) rejects before `McpRuntimeOwner` takes the transferred root, so nothing closes it. A probe with a later failure cause was not run (it would change the scenario's trigger, which the protocol does not allow the coder to do).

Resolution: both fixed in `T6.P6` (commit `68eb7ed3d`, red log `tmp/pr3911/T6.P6/red-1.log`). Failure 1: `McpRuntimeOwner.closeAdmission()` now closes the owned definition root's admission synchronously. Failure 2: `createAgent` releases caller-transferred `'agent'` definition, filesystem, LSP and memory owners when it rejects. The scenario file `workspace-definition-transfer.behavior.test.ts` was committed with `T6.P6` (it is the red test); all three scenarios pass with assertions unchanged.
