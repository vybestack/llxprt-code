## Helper H-c (created in this batch)

Two files under `packages/agents/src/api/__tests__/helpers/`:

- `gated-recording-mcp-server.ts`: the stdio MCP server process (run with `process.execPath`). Arguments: effects file, tool name, optional release file. It publishes one tool under the given name. Each call appends one JSON line `{"event":"entered","arguments":<call arguments>}` to the effects file; when a release file argument was given it then returns only after that file exists (and stops waiting when the request is cancelled), and appends `{"event":"finished"}` before returning.
- `gated-recording-mcp.ts`: the test side. `createGatedRecordingMcp(options)` makes a temporary directory with the effects and release file paths and returns `mcpServers` ready for `AgentConfig.mcpServers` (or `Config` parameters), `tool(agent)` (waits for `agent.mcp.discoveryState()` to be `ready`, which `createAgent` does not wait for, then returns the discovered tool's handle), `effects()`, `entered(count)`, `release()` and `close()`. No prototype spy, no capture, no `runtimeFactoryBindings`.

This file does not call H-c: its only `adoptPrepareSessionTools` use throws to fail session assembly, and an MCP tool cannot fail construction. The first consumer is T6.B29. H-c is checked in this batch by a throwaway test that drives it through `createAgent` (ungated: tool call returns and the effects file holds `entered` with the arguments and `finished`; gated: the call stays pending after `entered()` until `release()`; `helper-check-4.log`, 2 pass); the test is not committed.

## Scenarios

All eight scenarios share the local `reportWire()` loopback HTTP server and `withConfig` working-directory helper, which stay as they are. ### 2. `isolates same-label shared-Config report roots when closing first` / `... second` (one `it` in a loop, two cases)

Assertions: first agent's `issue.create` asks for an `info` confirmation and its `llmContent` contains `OWNER ONE`; second agent's `issue.view` has no `error`; `firstWire.accepted()` is `['issue.create']`, `secondWire.accepted()` is `['issue.view']`; a retained invocation of the agent being closed rejects with `closed` while `dispose()` runs; the peer's `issue.view` has no `error` after the close; the closed agent's own wire client still answers `issue.view` with `number` 2.

Outcome: **Kept** (isolation between roots, both closing orders; never Removed). Agent-level, `createAgent`. Both agents get `sessionId: 'same-report-label'`, the same `workingDir` and their own `githubBrokerClient`. The shared `Config` instance cannot be passed to `createAgent`, so "shared Config" becomes "same session label and same working directory" (slice proposal). Every `expect` stays.

### 6. `aggregates failed construction with explicitly transferred broker disposal and leaves the caller Config usable`

The invalid input is the empty `sessionId`: `parseAgentConstruction` calls `validateAgentRuntimeId`, which throws on an empty string (`agentBootstrap.ts:113-125`), and `assemble()` has already assembled the broker (`agentRuntimeAssembly.ts:206`), so the catch at `:213-227` aggregates the primary with the broker cleanup failure.
