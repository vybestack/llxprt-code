## Route and decisions

The old fixture hand-built a caller engine (about 150 lines: `Config`, `RuntimePolicyOwner`, `buildTestMcpRuntime`, `SessionSettingsOwner`, provider manager, OAuth manager, session client owner, rollback steps) and passed it to `fromConfig` with `sessionIdentityOwnership: 'config'`, a `FailingOAuthRelease` as the agent's OAuth manager and a `FailingLocalProvider` registered on the caller manager. It now builds through the foreground preflight route the CLI uses (Route B):

- `openRouteBPreflight({ authority, contributions, config })`, then the test's own `SessionSettingsOwner` over `route.settings` passed as `route.prepare({ settingsOwner })` (production borrowed-settings input, which also binds telemetry on it), then `route.createAgent(buildNonInteractiveActivationIntent(...))` inside `runNonInteractive`'s `acquireAgent`, the way the headless host does. `hasActiveProvider` and `isTrustedFolder` read `route.preflight.hasActiveProvider()` and `route.trust.isTrustedFolder()`.
- `FailingLocalProvider` (stream one chunk, then throw `local provider primary failure`) is a provider contribution (`failing-local`, a contributed alias, not a built-in id), selected as the Config's provider in the primary case. The non-primary case uses the `fake` provider and the `LLXPRT_FAKE_RESPONSES=plain-text.jsonl` replay seam (set and restored by the fixture; contributions and the replay seam are not combined).
- `FailingOAuthRelease` has no production input (`adoptOauthManager` is never set). The real cause is a failing token-store retirement: a `CredentialAuthority` wrapper delegating to the `OwnedCredentialFixture` authority whose `createTokenStore()` returns the real proxy token store and makes the first close of its client close the transport and then throw `oauth cleanup failed`. The production owners that close it (`AcquisitionRelease` 'tokens' step and the OAuth manager's retirement) surface it through the foreground Agent's disposal ("Agent dispose failed with 2 error(s): oauth cleanup failed; oauth cleanup failed"). Per-store first-close failure is a test-local instance wrapper on a client object the test owns, not a prototype spy.
- The telemetry outfile is replaced by a directory before the run with `rmSync(outfile, { force: true })` then `mkdirSync`; the file does not exist before the Agent is created on this route (the old fixture activated its client before replacing it), and the final state is identical.
- `verifyBorrowedTelemetry` is unchanged in meaning (records an event on the borrowed settings owner's telemetry after the Agent is disposed, flushes, reads the outfile).
- `rollbackSteps`/`settleEngineRelease` and the unused `Config`/manager/MCP/session-owner construction are gone with the caller engine; setup failures roll back through `cleanupAfterFailure(setupFailure, close)`.
