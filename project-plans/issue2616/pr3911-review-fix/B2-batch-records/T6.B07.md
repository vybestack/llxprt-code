## Unobservable reads

Barrier file, `media.store.getStoredByteLength()` (0 while the image is held; rejects `/closed/` after close). On Route B the `SessionMediaOwner` is built inside the preflight (`fromConfig-session.ts` `acquireActivationSettings`) and has no public read or input. Orchestrator ruling applied: observe `<route.config.projectTempDir>/media-live/*`. `LocalMediaStore` creates its directories when it first admits media (`local-media-store-persistence.ts` `ensureDirectories`) and `SessionMediaOwner.close()` removes the root, so the directory is a real effect only after media was admitted. Neither the image operation (it writes the output path and never touches the store) nor any `AgentProfilePreflight` or `AgentActivationOperation` member admits media before the Agent exists (`readHistory`/`captureHistory` read only), so with the preflight alone the directory is absent whether or not the store closes.

Final state (T6.F9, after the phase 6 review found the first replacement vacuous):
- Scenarios 1 and 2 (the adoption publishes an Agent): after the join the test admits real media through the published Agent (`agent.setHistory` with a PNG media block). `media-live` then holds exactly one store directory (the transferred store is still open after the activation was retired), and holds none after `agent.dispose()` (the receiving Agent closes it). Both counts discriminate: the first fails if the activation closes the transferred store during the join or rollback, the second fails if the Agent's disposal omits `SessionMediaOwner.dispose()`.
- Scenarios 3 and 4 (cancelled adoption and intent-mismatch rollback, no Agent): no allowed input admits media into the preflight's store, so "store open while the image is held" and "store closed after the activation releases it" cannot be observed through a real effect. The earlier `liveMediaStores(...).toHaveLength(0)` checks in these two scenarios were vacuous (the directory is absent whether or not cleanup ran) and are removed rather than kept as coverage. The kept `route.filesystem.paths.directories()` `/disposed/` assertions cover that the `afterClient` owners (definitions, media, trust cleanup and filesystem, which `retireActivationOwners` retires together) ran after the join, not media specifically. UNRESOLVED under the stop rule: media store release ordering on the rollback paths needs a public media admission on the preflight, or a production seam supplying the preflight's `SessionMediaOwner`; neither exists.
- "Store open and empty while the image is held" (4 assertions): not expressible for the same reason (no media can be admitted before the Agent exists).
