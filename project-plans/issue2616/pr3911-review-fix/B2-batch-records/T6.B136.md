## Decisions

- Scenario 7 of `generate-options`: the detached-client count is observed through the public `tokenizerFactory` input (approach (b)) instead of a domain-level `SessionClientOwner` test, because the file's only client-lifetime read is "no detached client acquired for empty input", and the first step of that acquisition is observable on a public input. If the orchestrator wants a domain-level test as well, it needs a `gemini`-named provider on a `SessionClientOwner`, which `openClientOwner` cannot supply without a helper change.
- The alias `gemini` in a custom contribution registry: `buildProviderContributionRegistry` rejects an alias only when it equals a registered provider id, and Gemini is contributed by the google-gemini plugin, not by the built-ins (`builtinContributions.ts`).
