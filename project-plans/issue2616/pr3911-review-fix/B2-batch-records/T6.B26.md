## Decisions

- Prompt directory: `fromConfig.behavior.test.ts` now calls `useConsumerPromptDirectory()` (the helper `config-injection.spec.ts` uses). The test-storage isolation resets the global config directory between tests, while the process-wide `PromptServiceManager` stays initialized against `<global config>/prompts` (`packages/core/src/core/prompts.ts` `doInitialize`). The first agent's turn installs the prompts; a second agent in the same file then fails with `Core prompt not found` (seen in `tmp/pr3911/T6.B26/after-fromConfig-1.log`). This is test setup, not an assertion change; the same fix is in `fromConfig-properties` and `fromConfig-tokenizer-readiness` through their existing `LLXPRT_PROMPTS_DIR` setup.
- `fromConfig-tokenizer-readiness` scenario 2, stale-Config divergence. Producing a real divergence through public inputs (`AgentConfig.provider: 'openai'` or an unknown name, with `activation` for `fake`) does reach readiness with provider `fake` but model `placeholder-model` (`after-fromConfig-tokenizer-readiness-2.log`), a different state from the original's single patched getter, so it is not a faithful stand-in and the scenario is recorded without it. The orchestrator may want to look at that behavior separately: with a `Config` provider that differs from the activation provider, `createAgent` prepares the tokenizer for the placeholder model, not for the activated model. It is not a failure of any Kept assertion in this batch.
- Scenario `T2a` in `fromConfig.behavior`: intent is `{ sessionId }` only, as before (no activation); the Config's own provider and model come from `openRouteAAgent` defaults (`fake`, `fake-model`).
- Not touched: `helpers/caller-fixture.ts` (still imported by other files; deleted in T6.D2a).
