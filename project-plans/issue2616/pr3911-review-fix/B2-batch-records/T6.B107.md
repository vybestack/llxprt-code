## Decisions

- Policy: the original forced confirmations and added an ALLOW rule for `external_record` on a caller policy owner (`addRule`, observation rule row "Rules added to a caller policy owner"). Production route: the MCP server's `trust: true` (H-c default) gives the tool no confirmation, and Route A (`fromConfig`) does not force generic confirmations. The `decision` and `awaitReady` parameters of the old `owner()` are used by none of owner-7..9 and are not carried into the helper; B105/B106/B108 add them if they need them.
- Effects: the original `effects.push(name)` ran in the owner's `MockTool.execute`. `effects()` maps each `entered` line of the owner's own MCP server (one server and effects file per owner) to the owner's label, as in T6.B103.
- Gates: the `entered`/`finish` gates become the H-c gate (`entered()`, `release()`); the afterEach releases every owner's gate before disposing (the helper's close order: release, dispose agent and `Config`, remove the MCP directory). The renderer-callback `entered`/`finish` gates in owner-8 are test-local state of the scenario and are unchanged.
- Request name: the old requests called `external_record`; the agent's name for the MCP tool is `mcp__recording__external_record`, read from the discovered handle (`owner.toolName`). The replay file uses the same qualified name.
- Model turns (owner-7): the `generateChatCompletion` spy (reached through `fixtureAgentResources(agent).manager.getProviderByName('fake')` and `wrappedProvider` unwrapping, `FakeProvider` `instanceof`) is replaced by the replay seam. `turns` `toBe(2)` was observable only through that spy; per the standing ruling the count is dropped and the same scenario keeps the effect assertions (`effects`, `completed`, display) plus a new `agent.getHistory()` assertion that the second turn (`Finished`) was consumed. The `spyOn`/`mockRestore` pair went with the spy. Expect calls: before 8, after 7 (the `turns` expect replaced by the history expect, plus `waitFor` retry variation).
- `borrow()` (owner-9): see Removed groups; the second agent is `fromConfig` (public entry) on the first owner's `Config`, `SettingsService` and `CredentialAuthority`, and waits for MCP discovery before use. It is disposed with the owner. The first agent's disposal does not close the borrowed `Config`, so the second agent works without production changes.
- Unused imports (`FakeProvider`, caller-engine imports, `MockTool`, `PolicyDecision`, prompt-system setup with `LLXPRT_PROMPTS_DIR`) went with the hand-built engine; the three scenarios pass without the prompt directory.
- Expect counts: owner-7 8 -> 7, owner-8 6 -> 6, owner-9 9 -> 9.
