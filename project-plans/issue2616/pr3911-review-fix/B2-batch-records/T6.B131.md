## Construction decision

The spec lives in `packages/providers`, which does not depend on the agents package (`git grep llxprt-code-agents -- packages/providers` is empty), and the batch protocol's providers section says to stop when an agents test helper is needed. The spec already imports `owned-credential-fixture.js` and production modules from `agents/src` by relative path; it keeps those imports and adds `fromConfig` (production entry, `agents/src/api/fromConfig.ts`) by the same kind of path. It does not import `route-a-agent.ts` (H-a): H-a selects the fake provider through the replay seam, while scenario 9 calls `setProvider('openai')` on a default-provider agent, and the old spec built `Config`, `SettingsService` and the authority itself. The local `openFirst`/`openSecond` become one `openAgent` that builds the same `Config` and `SettingsService` and calls `fromConfig(config, settings, { sessionId: runtimeId }, credentials().authority)`. `SessionSettingsOwner`, `owner.bindTelemetry`, the caller-supplied `ProviderFileLifecycle` (position 10) and `runtimeFactoryBindings` (position 13) are not production inputs and go.

2. `awaits session file deletion on the owning lifecycle before disposal`. Assertions: `cleanupScope` `failed` 0; `deleted` `['owner-file']`; `dispose()` resolves undefined. **Kept**, trigger moved: the explicit `cleanupScope` has no Agent member; `agent.dispose()` runs `releaseAdoptedFileScope`, which throws when `failed > 0`. `failed` 0 is carried by `dispose()` resolving; `deleted` is asserted after it, unchanged.
3. `keeps a failed file on its exact owner and retries deletion without touching a same-label sibling`. Assertions: cleanup `failed` 1; `deletionFailures` contains `owner-file`; `first.dispose()` rejects `Provider file cleanup incomplete`; after `unavailable = false`, retry `failed` 0 and `deleted` `['owner-file']`; `observedSecondConfig` `toBe(secondConfig)`. **Kept** (failure reporting, isolation). `failed` 1 is carried by the dispose rejection (the message contains `failed=1`), asserted with a pattern; `deletionFailures` read from `first.captureProviderFiles()`; retry through `first.retryProviderFileDeletions()`. `observedSecondConfig` identity (Observation rule row "Internal identity", approach (c); `adoptRuntimeFactoryBindings` is never set in production, field removed in T6.D2b) is dropped and covered in the same scenario by the sibling reads `second.captureProviderFiles().retainedFiles` `toBe(0)` and `second.dispose()` resolving.
4. `waits for the last lease before finishing deferred deletion`. Assertions: `cleanupScope` `deferred` 1 while a lease is held; after release and `waitForScopeCleanup`, `deleted` `['owner-file']`. **Kept**, trigger moved: `first.dispose()` starts with the lease held and is still unsettled after one microtask with `retainedFiles` 1 and `deleted` still empty (carries `deferred` 1); after `lease.release()` it settles and `deleted` is `['owner-file']`.
5. `does not delete retained workspace files when the session ends`. Assertions: `deleted` `[]` after session cleanup and dispose. **Kept** via `agent.retainProviderFile` with the workspace policy (`policy.scope: 'workspace'`; the policy scope, not `scopeId`, decides which cleanup deletes it, so `retainProviderFile` fixing `scopeId` to the runtime scope does not change the scenario) and `agent.dispose()`.
6. `separates lifecycles even when foreground owners use the same label`. Assertions: `firstFiles` `not.toBe(secondFiles)`; `secondFiles.snapshot().retainedFiles` 0; `second.dispose()` resolves; first still unsettled; after release the first settles. **Kept** (isolation). The lifecycle `not.toBe` is dropped under "Internal identity" (c); covering assertion in the scenario: `first.captureProviderFiles().retainedFiles` is 1 while `second.captureProviderFiles().retainedFiles` is 0 (fails if the two agents shared a lifecycle).
7. `cleans only the requested owner lifecycle for two equal-label owners`. Assertions: `releaseAdoptedFileScope(firstFiles, ...)` deletes only `a`; `b` empty; then the second scope deletes `b`. **Kept** (isolation). `releaseAdoptedFileScope` is what `agent.dispose()` runs, so the test calls `first.dispose()` then `second.dispose()`; assertions unchanged.
8. `rejects cleanup when a caller supplies no provider-file owner`. Assertion: `releaseAdoptedFileScope(undefined, ...)` rejects `cleanupScope`. **Kept**, no B2 fixture; unchanged.
9. `disposed foreground authority cannot be used again while its same-label sibling remains owned`.
