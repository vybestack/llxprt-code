## Production failures

1. **Fixed by T6.P3 (commit `294c35bcb`, `fix(agents): fire the final SessionEnd hook before its dependencies are retired`):** `SessionHookOwner` now builds its `HookSystem` at construction, while the trust authority is live, so the final SessionEnd no longer constructs it after the trust lifecycle is disposed. Scenarios 2 and 3 pass unchanged (`tmp/pr3911/T6.P3/after-shutdown-1.log`, 9 pass). Original finding:

   `hook-session-shutdown.behavior.test.ts`, scenarios 2 (`retains the physical final hook in its facade when the client owner closes first, once and without retiring its peer`) and 3 (`joins one delayed final hook across concurrent and reentrant disposal while retaining its peer`), both Kept as written (assertions unchanged, only the build and the removed `owner.dispose()` step differ).

   Symptom: on the production route (`fromConfig` over a `Config` with `enableHooks: true` and only a `SessionEnd` command hook), the first `agent.dispose()` of an agent that has had no earlier hook activity rejects with `AggregateDisposeError: Agent dispose failed with 2 error(s): Workspace trust lifecycle is disposed; Workspace trust lifecycle is disposed`. Scenario 2 fails in the `agent.dispose()` / cleanup; scenario 3 fails in `waitForMarker(.../entered)` (the final hook never runs: `startup=[]`) with the same disposal error.

   Cause (read from the stack): `fireFinalSessionEnd` (`agents/src/api/control/hooks.ts:229`) -> `SessionHookOwner.fireFinalSession` -> `requireSystem()` (`core/src/hooks/session-hook-owner.ts:217`) builds the `HookSystem` lazily at dispose time -> `new HookSystem` subscribes to trust changes (`hookSystem.ts:118` -> `WorkspaceTrustLifecycle.subscribeTrustChange`), and the agent's `WorkspaceTrustLifecycle` has already been disposed by then (`workspace-trust-lifecycle.ts:159`, `assertActive`). A hook system that already exists (any earlier hook event, for example scenario 1's `triggerSessionEnd()` or the `BeforeAgent` turns of scenarios 4-9) does not hit this, so those scenarios pass. The fixture route created the hook system earlier, which is why the scenarios passed before.

   Single-agent reproduction without any scenario code: a temporary probe (`fromConfig` + `SessionEnd` hook, `agent.dispose()` first, no turn, no trigger) fails the same way with one agent and with two; probe output `tmp/pr3911/T6.B27/production-failure-1-probe.log` (the probe file was deleted afterwards). Full scenario output: `tmp/pr3911/T6.B27/production-failure-1.log` (2 fail, 7 pass).

   Scenarios to carry into the T6.Pk red test: `hook-session-shutdown.behavior.test.ts` scenarios 2 and 3 exactly as written in the working tree.
