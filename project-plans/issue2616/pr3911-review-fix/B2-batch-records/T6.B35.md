The orchestrator decisions were applied. `withPreflight` no longer has the `observeActivation` flag (its last parameter is now optional provider `contributions`), the `observeActivationPreparation`, `captureActivationConstruction`, `capturedActivation` and `capturedSessionClient` imports are gone, and the file has no prototype capture of the activation or the session client. The only remaining spies are the ones that were in the file before the batch (`ProviderManager.prototype.setConfig`, `config.getPolicyEngineConfig`, `AgentClient.prototype.getHistory`, `AgentActivationBootstrap.prototype.createForeground`).

- U1 (scenario 2, 2 runs). Domain-level Replaced was tried first and is not constructible: `AgentActivationBootstrap.createForeground` is reached only through `AgentProfilePreflight.createForegroundAgent`, and the owner is built only by the private `PreparedActivation` class inside `preflight.#prepareActivation` (`profile-preflight.ts:690`), which sets no tokenizer input (`activationTokenizer` is a protected field that only the `ActivationFixture.acquire` test subclass fills, with hand-set protected fields, so it is not production-filled). `AgentConfig.tokenizerFactory` is Route C, which does not go through `createForeground`. Outcome: the held-`getHistory` variant (as scenarios 5 to 7): a public `activation.readHistory()` is held, `createForegroundAgent` waits in `#joinPublicWork`, `activation.dispose()` stays pending, and after release the publication rejects `AbortError`, closing resolves, borrowed settings check and `readHistory()` rejects `disposed` all keep. Lost coverage: the hold is before the token is consumed and before foreground MCP construction, so the rollback of an abort that arrives after the token is consumed (during the tokenizer wait in `finishForeground`, and `#constructForegroundMcp`) is not exercised by this scenario. Outcome stays Kept (disposal order), assertion form unchanged, hold point changed.
