## Contract and ownership

Assembly belongs in `packages/agents/src/api/`, beside `agentRuntimeAssembly.ts`, `fromConfig.ts`, and `createAgent.ts`; core cannot import agents. Introduce one explicit session lifetime owner for the five existing ports: `SchedulerHandle`, `TaskPort`, `ShellJobPort`, `ApprovalBusPort`, and `RecordingPort` from `packages/core/src/session/sessionExecutionServices.ts`. Use `SessionSchedulerRegistry` for object-identity acquisition. Keep durable settings, policy configuration, workspace paths, and caller-owned configuration on `Config`; move live service construction, publication, and disposal out of it. Inject narrower ports into core and CLI consumers instead of passing Config solely to look up a session service. Do not make the owner another generic Config-shaped locator.

`fromConfig({ config, ... })` **adopts the exact caller-supplied Config**, as asserted in `packages/agents/src/api/__tests__/fromConfig.behavior.test.ts`; it does not dispose that Config. It must construct a fresh session lifetime owner and use the caller-supplied `messageBus` by identity if provided. `createAgent` uses the same session assembly but continues to own and dispose its own Config. A borrowed bus or other caller-supplied resource stays usable after agent disposal. Two independently created sessions may have equal *label strings* but cannot share a scheduler, task manager, shell manager, approval wait, listener, or recording; avoid using a single mutable Config as the two-session test fixture. The existing `FromConfigOptions` in `packages/agents/src/api/config-types.ts` is the adoption entry; do not invent a second `fromConfig` API.

The session shutdown sequence is explicit: stop new admissions; abort active requests and pending authentication/approval waits; cancel and join children, async tasks, and shell jobs; flush and dispose recording; release scheduler entries and listeners. Repeat and concurrent dispose calls share one cleanup attempt; attempt every release and report all failures with `AggregateError` rather than losing the original failure. On partial bootstrap failure, release session-owned resources without disposing an adopted Config. Preserve the #2320 bus rule: confirmation is bound to agent and invocation identity, responses route by correlation ID, and there is no implicit bus fallback. A session's scheduler is built against its own bus and tool registry; the first acquisition's construction dependencies remain fixed while `setCallbacks` refreshes the acquisition callbacks.
