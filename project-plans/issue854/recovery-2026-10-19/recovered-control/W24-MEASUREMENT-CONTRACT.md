# W24 history-retention measurement contract, 2026-10-20

## Decision

Use `pinned-code-v1` as a named candidate measurement mode. It sets only `BUN_JSC_forceCodeBlockLiveness=true` before Bun starts. Baseline JIT, DFG and FTL remain enabled. It neither modifies application functions nor retains history in a JavaScript holder. The original default-runtime test and its failing evidence remain separate. This contract does not close W24 or assert that default-runtime total heap passes.

The positive and retaining control must use the same mode, source, 530 warmup turns, ten baseline turns, 50 measured turns, 60 measured provider requests and five tool rounds. Text size, turn sequence, nine readings per checkpoint, 290000-ms timeout, 1,048,576-byte peak allowance and 262,144-byte late fitted/endpoint bounds remain unchanged. No heap subtraction, value-dependent sample deletion, additional warmup, retries or threshold changes are permitted. All accepted memory readings are the original unfiltered `settledHeap()` values.

## Why pin compiler objects

Root D attributes the returning allocations to existing static functions, including `AgenticLoop.scheduleAndAwait`, not newly generated scripts. Its standalone default probe established code aging, recompilation and optimized `Output` liveness beyond 64 seconds. The installed runtime exposes no public per-code-object pin API. Its actual option dump exposes `forceCodeBlockLiveness`. The supporting WebKit source routes this option through `CodeBlock::shouldVisitStrongly`, returning true before age/optimization weak-liveness decisions; `visitChildren` traces strong and weak code references. That can increase retention. It cannot remove a live strong history reference from the collector's graph. This is an intentionally stronger residency condition, not a claim that compiler memory has a universal bound.

The local real-policy probe with only this flag preserves 2,040 code blocks across 6.5 seconds. The actual policy method compiles to DFG, with its count changing from zero to one. Unfiltered heap is 21,312,420 / 21,335,636 / 21,337,224 bytes across warm/age/recall. Retaining 64 decoded rows raises it to 25,576,442; releasing them returns it to 21,368,697. These small probes select the mechanism, not the full-product result. A plain interpreter probe still loses 1,912 code blocks with age, so disabling JIT alone does not solve the measured mechanism. A baseline-only experiment is retained but is not the selected mode.

No code category is removed from the accepted meter, including dynamic code and code-held data. Pinning could expose extra profile-held objects or later compilation, and either must still fit the original raw bounds. The full positive may fail. No later mode switch or opportunistic full-run retry is authorized by this contract.

## Data coverage and controls

Five independent controls allocate decoded text rows, separately decoded cloned text, Buffer-backed media-sized data, numeric arrays, or a growing ID-to-number Map. They retain no original row in the last four cases. Each positive/control pair has an identical input digest and identical runtime mode; only the strong holder changes. The original unfiltered heap predicate must accept release and reject retention in both default and pinned modes. These controls exercise JavaScript cells, string storage, native buffer storage, numeric-array backing storage and aggregate identifiers. They are meter qualification, not replacements for the real Agent workload or proof that the full fixture sends media.

Default-mode supporting censuses retain every reported type and total. Their projected history-data total includes plain objects, arrays, strings, buffers, typed views, maps/sets and backing-store categories. It is not a complete byte meter. Actual controls found that Inspector snapshots omit most Buffer and numeric-array backing storage: roughly 3.6 MB of raw retention appeared as only 8–10 KB of graph data growth. V8 encoding includes Buffer storage but still omits numeric-array storage. Neither encoding is used to waive a raw memory failure. Genuine buffer/array leaks must fail the unfiltered predicate even when projected census bytes miss them.

A separate default-runtime diagnostic uses the same real Agent, OpenAI conversion/HTTP path, slash checkpoint dispatch, scheduler/write-file tool, recording and compression operations for 20 fixed warmup and 20 fixed measured turns. It observes every decoded row, including repeats, through weak references, rather than only the first row per reader. It reports all graph categories, raw heap and native extra memory, and compares an identical-input strong-row holder. All observed rows must release normally and remain alive with the holder; projected data must reject the holder. It is deliberately shorter than full acceptance. Snapshots perturb raw heap, which remains reported without filtering. Its graph coverage and independent native-storage controls supplement the pinned raw-heap proof; its projected totals alone cannot establish absence of arbitrary native leaks.

Snapshot processing does not run inside the pinned raw-heap control or full-product acceptance lane. A development control mixed snapshot parsing with pinned JIT code and produced a first-checkpoint 2.38 MB transient, disappearing at the next checkpoint. That failure is preserved. The final lane separates the diagnostic observer from the raw meter rather than changing the raw predicate or dropping the failed sample.

## Qualification limits and remaining work

A successful pinned lane would establish bounded history retention with production JIT tiers enabled under stronger compiler-code liveness. It would not establish default executable-cache stability, a universal compiler-cache cap, default raw-heap acceptance, media-provider conversion coverage, recording-as-primary topology, or W24 completion. Existing default failures remain diagnostic obligations with their original assertions. The next topology slice and its cost measurements remain independent. No default flip, OCR, cleanup, push or merge belongs to this work.

## Frozen result and test layout

The frozen full positive passes at 283,459 bytes peak growth, with late fitted/endpoint growth 208,429.5/208,746 bytes. Its identical-input retaining trap rejects at the memory assertion: 196,975,196 bytes final growth and seven predicate failures. Both use the declared mode, fixed complete input and unchanged bounds. `W24-HEAP-METHOD-E.json` binds the receipts, final option dumps, source inventories and independent native controls. This accepts the named method only. The original full default-runtime RED receipt is preserved, not converted into positive evidence by the shorter default census.

The ordinary required command from `packages/cli` is `bun test ./src/ui/hooks/whole-product-pinned-heap.test.ts`. It launches a fresh process with the declared code-liveness flag and executes the byte-identical measured worker `whole-product-pinned-heap.fixture.ts`. This keeps JSC policy local to that worker. The original default entry is preserved byte-for-byte as `whole-product-heap.diagnostic.ts` and remains executable with `bun test ./src/__tests__/heap-workers/whole-product-heap.diagnostic.ts`. It retains every original assertion and may fail; it is a diagnostic outside the required qualified-method contract, not a skipped or inverted test. The worker is required through its launcher; no discovery or enforcement rule changes.

Code-block liveness selection is narrower than arbitrary object pinning, but code profiles can reference data. The method does not promise that only code bytes change residency. Any additionally retained profile-held data remains included in the raw meter and must fit the same bounds. Application cache limits, strong history ownership and data collection policy are otherwise unchanged. Ordinary-runtime census and raw native controls cover complementary cases, including payload copies that leave no original row WeakRef alive. No result here authorizes subtraction of unknown growth or a claim that all future default-runtime heap growth is compiler code.
