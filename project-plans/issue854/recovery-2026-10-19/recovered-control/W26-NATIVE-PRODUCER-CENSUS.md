## Implemented boundary

The public session helpers now hold the native checkpoint and select a raw prefix cut from pinned ROW entry speaker metadata. Raw ranks, service-curated ranks and provider units remain distinct. `NativeHistoryPrefix` carries the cut and borrowed version, then writes retained rows through `HistoryStorePort.publishDetached` using `appendDerived`. No history-sized array, ID map or copied rollback journal replaces the removed files. The existing writer recognizes a prefix and publishes its rewind. Existing client reset bookkeeping still runs.

The original complete restore/checkpoint file exposed two checkpoint regressions: recording fan-out had not been awaited before a subsequent successful restore returned, and the new branch lacked temporary reservations for removed media needed by rollback. The follow-up awaits `waitForCommit` on successful prefix publication and compensation. A checkpoint media iterator checks ROW media flags and block directory kinds, decoding only reference blocks. Reservation and release each traverse pinned metadata and referenced blocks, never full text rows; repeated IDs use the media store's existing idempotent owner reservations. No per-operation media trie or history path map is introduced. The shared reader scope accepts typed row or reference iterators with unchanged retirement/error ordering.

Public sessions serialize these operations. A captured mutation mark rejects a stale prefix before detached-transform admission; checking that mark inside admission falsely rejects the operation's own mutation. Source length is checked again inside the transform. This is not a new general concurrent-rewrite API.

The CLI follow-up selects raw human positions from the existing row-tree speaker aggregates. The selected three-query experiment uses four reads at 40 rows and eight at 4000 rows; caches remain within the existing 65536-byte per-cache cap. Oversized reverse cuts return directly from the aggregate count. Speaker facts already exist in the format and require no codec-width or generation change. Empty or invalid AI rows remain raw positions, and human speaker counts do not use curated or provider-unit ranks. Append, insert, rewrite, pop, version restore, copy and reopen preserve those counts.

Two full media metadata/reference passes remain separate from indexed selection and retained-row conversion. The whole operation is not logarithmic. Actual media ownership-index and reservation files remain a named Phase 8 boundary, while non-media CLI operations create no operation files. Held request consumers reserve their current blob before concurrent clear; their immutable bytes survive janitor until awaited completion/abort release. This does not protect unread media or replace provider shared-reservation bookkeeping. No global cache, pin or retained-heap capacity claim is added.
