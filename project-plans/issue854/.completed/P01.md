## Fix Session: lazy journal creation (2026-09-18)

**Defect found in smoke.** The original wiring called `createScrollbackJournalForSession(props.initialRecordingService, ...)` once during render (WeakSet-guarded one-time swap). `SessionRecordingService.getFilePath()` returns null until the first content-class event materializes the session file (enqueue gates on MATERIALIZING_EVENT_TYPES; materialize at SessionRecordingService.ts L257/L351, getFilePath L502), so at bootstrap time the path is always null, the eager create returned null, and the journal was silently never created — no `sb-*` sidecars in any real run. The journalWiring.test.ts fakes always returned a ready path, which is why the tests missed the ordering. The earlier deviation note 2 ("headless smoke does not mount the interactive AppContainer") rationalized the missing sidecars instead of catching this; that note was wrong about the cause and has been removed.

**Fix.** Journal creation is now lazy at the commit points:

- `createLazyScrollbackJournal(recordingService, enabled)` returns a `LazyScrollbackJournal` handle whose `current()` re-resolves on every call: null while the flag is off or the recording has not materialized a path; creates the journal at the first commit past that; and when the recording path CHANGES (service swap on resume/branch, followed via `recordingSwapCallbacks.getCurrentRecording()`), closes the old journal and opens the new base — items already journaled stay in the previous session's file (correct per-session behavior). `close()` is idempotent.
- `wrapTurnCommandsWithJournal(turnStore, lazyJournal)` resolves the journal at each addItem/updateItem commit; WeakSet single-wrap guard unchanged; flag off leaves the commands byte-identical (call site only wraps when `ui.scrollbackJournalEnabled !== false`).
- `useAppBootstrap` lifts `useRecordingInfrastructure` above the wiring block so the lazy source reads the live recording service ref; the unmount cleanup closes the lazy journal.

**New tests (TDD, written first and failing on the missing export).** (a) path null at wrap time, becomes non-null later → journal created at first commit, `sb-*.jsonl` + `sb-*.idx.jsonl` appear, pre-materialization item stays out of the sidecar; (b) path changes → second `sb-*` pair gets subsequent items, first pair keeps its one item; (c) flag off → no files ever, commands still work. Real temp dirs; the only fakes are `{ getFilePath: () => ... }` closures, because getFilePath ordering IS the property under test.

**Smoke path finding.** The directed one-shot smoke (`bun scripts/start.ts --profile-load zai-glm-flash "..."`) exits 0 and renders the haiku, but a positional prompt makes `config.isInteractive()` false → `dispatchInteractiveOrNonInteractive` routes to `runNonInteractive` → the AppContainer never mounts, so no UI commit points exist and that command cannot exercise the journal wiring either way. The end-to-end proof therefore uses an interactive session: `script -q /dev/null bun scripts/start.ts --profile-load zai-glm-flash -i "write me a haiku and nothing else"`.
