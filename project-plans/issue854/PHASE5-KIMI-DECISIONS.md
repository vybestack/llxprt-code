## Source and emitted facts stay separate

Namespace 0 and namespace-4 kinds 0/1 still describe source occurrences. Their existing `lastEligibleCall`, counters and block coordinates are not presented as emitted facts. Namespace-4 fields 2/3 hold emitted calls/responses, field 4 holds five emitted counters, field 5 holds the last eligible emitted occurrence and field 6 marks exception-list admission. Keys are encoded as a field byte, u32 ordinal and the raw namespace-0 identity hash. Counts and last use ordinal zero. The OpenAI/Anthropic normalized namespaces remain independent and unchanged; raw `call_x`, `hist_tool_x` and `toolu_x` mappings do not merge.

An emitted occurrence is 20 bytes: unit position, row-local eligible rank, source block index and flags. The five u32 counters are call count, eligible count, AI call count, AI-adjacent response count and other-adjacent response count. These values contain no file offsets. They remain below the existing IdFact size discriminator, so clone/compaction copy them as opaque values; actual mapping queries and OffsetAudit cover copied versions. The existing bounded batch, spill writer and 64 KiB read cache remain in use. Current-row maps contain that row's IDs and occurrences only, not the history's IDs.

Version 6 rejects CRC-valid version-5 files. Version 5 admitted the Kimi marker without maintaining these fields, so accepting that version would make missing facts look valid. No migration or compatibility alias was added. The marker and all new fields use the existing commit/acknowledgement and poison path. Exception count is finalized after emitted contributions have run, before metadata publication.

## Eligibility and correction queries

Eligibility includes named calls with nonempty IDs across every emitted speaker. R1 reconstructed calls use the response name, with `unknown_tool` for the empty name. Unnamed calls cannot replace the last eligible occurrence. The position stores its eligible rank within its row, and pinned tree aggregates supply the global zero-based ordinal. Reading a name selects one source block, not the complete row. The returned name is copied through UTF-16LE so it owns its storage and preserves lone surrogates as well as ordinary Unicode. UTF-8 copying would change the former.

`kimiMappedId(rawId)` returns the last eligible name and ordinal, or undefined for an unmapped ID. Old pins read their own trie, metadata and row roots after later appends. `kimiIdFact` returns emitted counts, last occurrence, consumed unmapped uses and written uses. `kimiHolders(rawId)` streams the call list followed by the response list for that raw ID, preserving each occurrence's emitted position. It does not collect the holder set.

A clean ID has one eligible call in an AI unit. Other IDs with emitted calls enter namespace 5 once; `kimi:exc` stores the length. Ordinary unique recorded histories therefore have an empty list. `kimiExceptions()` streams those entries. `kimiUnmappedCount()` sums their per-ID consumed counters without reading clean IDs. This is a sparse lookup, not a populated `RowEntry.unmappedBlocks` aggregate.

Consumed and written uses differ. A fallback ID is consumed before the converter drops an invalid tool message. In particular, an unnamed AI call and its response receive different fallback IDs, so the response is dropped when the stream has AI calls. A human call's adjacent response is also dropped in that stream. With no AI calls, the converter's validator admits tool messages. Versioned `kimi:ai` distinguishes those cases without revisiting every earlier non-AI holder when the first AI call is appended.

`kimiDigitCorrection()` implements the mapped-exception term: written uses times the last eligible ordinal's digit width, minus twice the digit widths of that ID's eligible occurrences. It reads only exception IDs and their occurrences. It is not the complete Kimi byte/token adjustment. Conversion-order unmapped digit ranks, subtraction for dropped fallback uses, row-prefix `unmappedBlocks`, format-dependent name measurement and stored holder remeasurement still need the later summary/LENS integration. Mapping queries already return the changed name for both earlier call rows; no stale mapped ID is baked into a row.
