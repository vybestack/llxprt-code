# Anthropic numeric unit prerequisite, 2026-10-21

This increment does not implement the requested first complete native Anthropic format. It adds the row-local numeric facts and ten-state transfer stage, with an explicit boundary before native repair overlays. There is no Anthropic registration, stored LENS writer or request-length planner in this increment. Provider sends and the backend default are unchanged.

## Implemented

`anthropic-unit-facts.ts` calls the retained per-unit converters, row-local image sanitizer and cross-model thinking strip. It records JSON UTF-8 lengths, block kinds, blank flags, converted tool IDs and anchor flags for ordinary and chain conversion under both thinking variants. It retains no text, signatures, media bytes or result payloads in its returned facts. That property of the return shape does not prove retained heap over repeated native operations.

`anthropic-unit-transfer.ts` composes these atoms with supplied validator corrections into the existing 296-byte Anthropic slot shape. It implements the ten boundary states, assistant string-to-block merging, blank removal, placeholders, leading and trailing user additions, chain transitions and chain/last-thinking side tables. It imports no table, builder or phase-zero test implementation. Its output is a unit transfer, not an exact request plan without version-correct overlays.

`RowFormatSettings` gains a typed optional Anthropic member with explicit cache policy and per-image dimension/pixel budget. The whole member is hashed by the existing settings key and cloned/frozen by settings capture. The numeric converter requires explicit cache-off settings and refuses caching at 5m/1h, OAuth, tool-name transforms, unsupported-media rejection and stored-media references. Raw AI units carrying tool results are refused; native normalized AI units do not carry those results. Both reasoning-enabled values and both stored thinking variants are measurable. Last-kept selection is exercised only by the independent test oracle, not implemented as a native query.

## Evidence boundary

The new frozen differential visits all 5000 unchanged cache-off source inputs, normalizes them with the existing independent normalizer, and uses each input's drawn reasoning/model/image settings. It compares numeric length and message count with the actual old table emitter and the validated phase-zero model. The old emitter's UTF-8 SHA-256 equals the phase-zero reference output. This is not comparison of a new native writer's output, nor a claim that the original raw-form body hashes equal bodies after normalization. No frozen inputs or expectations are rewritten. Global repair overlays and last-kept group selection come from the test-only reference machine. They are not production dependencies.

## Why registration is not exposed

Raw normalized occurrence lists answer converted-ID membership and ordered successor questions, but those facts alone do not establish final conversion-message boundaries. The old wire path groups consecutive AI units into a signed-thinking chain before validator repairs. A pulled result can empty a later message, and result-media conversion can depend on the chain's conversion context. An earlier assistant's consumption also changes later eligibility. A per-row call to the existing builder, a whole-history chain scan or a request-local pointer map would hide that missing persisted state and violate the requested resource contract.

The next increment needs versioned per-unit conversion-group/repair facts, indexed chain boundary and prefix queries, message-level result consumption, and dependency-driven shadow remeasurement of affected rows before acknowledgement. Those facts must use native groups and the existing settings slots/generations. Existing eager Responses counterpart repair must remain intact. Only then should Anthropic registration publish complete LENS/summary stamps or a planner trust them. No unsupported setting or unmeasured zero should bypass that admission.
