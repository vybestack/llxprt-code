## Implemented boundary

The writer fills `RowEntry.unmappedBlocks` and its existing tree aggregate with conversion-time fallback consumption. Its emitted 20-byte occurrences store a fallback-within-row rank under flag 8, sharing the existing rank field with eligible occurrences. Native fallback indices use eligible total plus aggregate below-row count plus local rank. File version 7 refuses CRC-valid version 6 without a compatibility path. Row/aggregate/summary dimensions do not change.

Incremental append repairs older unmapped holders when an ID first becomes mapped, including other IDs' local ranks in the same row. Repairs stream selected-ID holders and update facts/tree before acknowledgement. Rebuild, fill, owner changes, reopen, fork, compaction, density, pop, compression, replacement, clear/refill and old pins are covered. Supplemental lifecycle assertions use nonzero consumed prefixes and OffsetAudit after physical copying. Current-row structures and existing byte-capped writer/cache remain bounded; repeated holder rows can be recomputed more than once.

`kimiWrittenDigits()` combines decimal-boundary summation, mapped-exception corrections and indexed subtraction for dropped fallback responses. Consumed count and written fallback count remain separate. Names containing Unicode, escaping and lone surrogates are compared through actual conversion, but digit totals are suffix digits only. No name/token/byte LENS metric is claimed.

`kimiCounterBefore(index)` projects the existing affected-row/tail overlay over pinned aggregate prefixes. Pending eligible duplicates remove earlier native unmapped holders without double-subtracting corrected rows. It accepts normalized unit indices and the end index, sharing query pin ownership and original-error cleanup. Native conversion prepares an occurrence array for one row, so repeated unmapped IDs consume distinct counters. It does not copy the Mistral selection cache or retain a history-sized ID map.

Query work is tree depth plus selected-row metadata and pending-ID holder corrections. Many historical unmapped holders of a pending ID can add a sparse occurrence-stream cost per query; this slice does not prove uniform O(depth) for adversarial duplicate histories. Full request-only digit-summary integration is still open. The native ID resolver also does not remove the converter's existing full observation pass for thinking/media/chat facts.
