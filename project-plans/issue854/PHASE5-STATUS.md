Native append and rebuild now persist normalized occurrence counts and positions over emitted units. Implementation is `9235a4420ad49bd9a15ce104c83a9de2c15781f6`, starting from `4e23b8fdc`. Phase 5 remains partial. Production provider sends still use the existing normalizer, and the default backend is unchanged.

## Implemented boundary

Namespace **1** stores OpenAI calls/results and namespace **2** stores Anthropic uses/results, using the existing count-at-ordinal-zero and position-at-ordinals-one-through-count layout. Positions are `(label, part, unit)`, not source block coordinates. The injected tools normalizers preserve empty-ID and prefix collisions. No second index or core-to-providers import was added.

The row writer derives occurrences from R1 reconstructed calls, stripped self units and adjacent response units. Reconstructed duplicate calls remain duplicate occurrences in one unit; each nonempty raw target contributes one adjacent response slot. Calls enter these lists only in AI units. Response placement follows targets of any speaker, including human calls and cross-speaker orphan completion. Raw human response blocks are stripped and relocated by normalization. This increment establishes lists for that emitted normalized stream, not a new raw-history Anthropic assembler path.

Append updates the new rows and prior call/reconstruction rows affected by their IDs before publishing the new trie root. It retains the existing path-copy contribution update. Rebuild streams source facts first, then headers and ID pieces through contribution and normalized-occurrence maintenance. It does not decode block payloads or retain all historical IDs. A list edit binary-searches the affected row's interval. If its size changes, the edit streams only that normalized ID/kind's suffix from a frozen trie root through bounded write batches; it does not collect the suffix or rebuild the whole journal on append. This can rewrite a long colliding-ID suffix. It is not constant-cost append for that case.

Current-row fact/list maps and distinct-ID sets are released after that row. The existing 65536-byte fact batch and fixed node caches remain. Normalized positions contain labels, not file offsets, so clone/compaction preserve them while the existing copier remaps row/trie offsets and `mappedRef` values. Native mutation assertions compare persisted lists after pop, owner/fill, purge, density, compression, clone and compaction.

The file version is now **5**. Committed version-4 writers could produce journals with contribution metadata but no normalized lists. Admitting them through the newly enabled query API would return false zero counts. A CRC-correct version-4 header now fails admission; version 3 remains refused. Layout widths are unchanged. No migration, fallback or further version bump was added.
